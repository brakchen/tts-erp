# PG 容器与端口边界

**为什么这个目录存在**：2026-11-09 实测发现 `install.sh` 从不创建容器（`docker run`=0、`docker create`=0），
端口绑定的 owner（`-p 5432:5432`）**只存在于服务器的命令历史里**，仓库中无任何声明。
⇒ 不把它固化下来，收口就只是一次性的：下一次重建会回到 `0.0.0.0`。

**实测到的三条事实**（决定了这里为什么这么写）：

1. **端口映射会把源地址 MASQUERADE 成 `172.19.0.1`** ⇒ `pg_hba` 里基于源地址的限源在这条路径上**完全无效**
   ⇒ 访问控制必须做在**端口绑定层**（`127.0.0.1:5432:5432`），而不是 `pg_hba`。
2. **卷必须挂 `/var/lib/postgresql`**，不是 `/var/lib/postgresql/data` ⇒ PG18 镜像的 `PGDATA=/var/lib/postgresql/18/docker`。
3. **网络是 `postgres_default`**，不是默认 bridge ⇒ 否则 `frpc`/其他容器找不到它。

**暴露面**：本机 5432 曾同时对 `0.0.0.0:5432` 与 `[::]:5432` 开放；组网内的 `aliyun-50`（公网机）
可 TCP 连上 `10.144.144.3:5432`。⇒ 收口目标绑定 `127.0.0.1`（`frpc` 在宿主机上走回环，**不受影响**）。

**重建**：`bash scripts/infra/postgres/rebuild.sh --dry-run` 看命令，`--confirm` 真执行。
