# 《SPU 盈利表现对比与变化提示》产品方案

> 文档版本：PRD 评审稿 v3 · 更新日期：2026-10-07。
> **已确认：7 天主参考、3 天看近期变化，不做阈值告警；无单但有广告费的 SPU 保留并重点标注，ROI 可计算时正常展示（包括负数），不可计算才显示横线。**
> **允许查看旧结果，但日期最多选到后台确认的最新可用日期；不规定试用人员、周期或效果评分，功能实现后根据实际反馈持续改进。**本文不是实现完成声明或上线批准。
> 本次只修改产品方案，不修改现有页面名称、访问地址或应用实现。

## 1. 决策摘要

**唯一目标：帮助运营人员看清 SPU 的盈利表现及其变化，为后续运营策略调整提供清晰、可信的数据依据。**

- **看谁：**从全局经营数据中查看持续运营的 SPU，也能核查指定 SPU。无单但仍有广告费的记录不能被当成无活动隐藏，应保留并重点标注。
- **看什么：**同一 SPU 两期的 ROI、净利润原值及变化，同时看订单数、广告消耗。可计算的 ROI 正数、零、负数都正常展示；不可计算时显示“—”并说明原因，净利润按实际值展示。
- **怎么看：**【已确认事实】7 天用于主要参考，3 天用于观察近期变化。分别与前一个等长、不重叠周期比较，不把 3 天涨跌单独当成持续改善或恶化。
- **不做什么：**【已确认事实】本版本不做阈值告警，不做告警/严重程度筛选、历史确认升级或告警数量统计；不自动给出加投、停投等策略结论。
- **用户得到什么：**能说清“盈利表现怎样、最近发生了什么变化、依据是否足够”，再由运营决定继续观察、查证或调整策略。

首版只围绕“选范围 → 看对比和依据 → 查盈利详情 → 人工判断”组织页面，不再扩展告警系统。ROI 与净利润可能方向相反，3 天与 7 天也可能方向相反；这不自动代表数据出错。

### 2.2 为什么采用 7 天＋3 天

2026-10-07 的只读数据复核覆盖两个越南店铺，截至店铺当地 **2026-10-06**。为保持比较范围一致，先按“库内累计已付款订单至少 3 单、近 7 天有出单”筛出 **23 个 SPU**；这只是本次复核范围，不等于最终默认活动条件已定稿。

| 同一批 SPU 的观察结果 | 最近 3 天 vs 前 3 天 | 最近 7 天 vs 前 7 天 |
| --- | --- | --- |
| 本期只有 0～1 单 | 20/23（87%） | 11/23（48%） |
| 两期都有出单 | 5/23（22%） | 18/23（78%） |
| 两期 ROI 都可计算 | 11/23（48%） | 19/23（83%） |

3 天有订单的 12 个 SPU 中，9 个只有一单；7 天本期有单则由筛选条件保证，不能把“没有零单”当成独立的稳定性证据。**累计至少 3 单，也不保证每个比较周期都有足够订单。**

用当前事实和估值回算过去 14 个截至日，在已有至少 14 天经营信号、两种窗口均可比较且方向非持平的相邻观察日配对中：

| 变化方向翻转 | 3 天 | 7 天 | 配对数量 |
| --- | --- | --- | --- |
| ROI 从升变降或从降变升 | 29.0% | 13.5% | 200 组 SPU×相邻观察日 |
| 净利润从升变降或从降变升 | 28.6% | 12.3% | 318 组 SPU×相邻观察日 |

经营信号以首次出单或正广告消耗为观察起点，不是已验证的上市时间。以上不是历史页面快照，也不是误判率：真实转折会产生翻转，滚动窗口相互重叠，ROI 可计算也不证明采集完整或足以决策。不能推广为所有店铺的长期最优周期。

结论是：**7 天与 3 天是及时性和稳定性的折中，不能当成同等可靠的证据。**3 天用于较早看到变化，7 天用于结合较多数据观察整体方向，二者都须结合实际订单和消耗。

另有 35 个累计至少 3 单、近 7 天无单的 SPU 仍有广告消耗，占该累计订单范围近 7 天消耗的 5.24%。因此“7 天无单”不能直接等同于停止运营；用户已确认这类记录纳入默认范围并重点标注。该汇总不代表全部无单投放 SPU 的数量。

复核采用同一计算快照、金额先聚合再计算的统一盈利口径，不平均日 ROI，不输出商品或订单行级标识；汇总证据可按协调任务 `spu-3d7d-recheck` 追溯。数据复核不是用户效果测试，也不证明源数据采集全部完整。

### 2.3 首版范围

**包含：**店铺与 SPU 范围、7/3 天对比、两期盈利原值和展示变化、无单但有广告费的重点标注、订单/消耗依据、最新可用日期与旧结果说明、已有盈利详情及失败恢复。

## 4. 用户路径与产品结构

1. **进入现有页面。**沿用当前访问权限；未登录或无权限先处理访问，不显示受限业务数据。
2. **选范围。**选店铺，默认查看持续运营范围，也可查指定 SPU；默认 7 天，可切换 3 天。日期最多选到该店铺最新可用日期，回显实际截至日和两段日期。
3. **读对比与依据。**先读两期 ROI、净利润，再结合订单数、广告消耗；重点查看“无单但有广告费”的记录。可计算的负 ROI 正常展示，少量订单、缺失和负数不自动变成告警。
4. **看近期变化。**按需切换 3 天；窗口改变只改变比较周期，不因 3 天无单或 ROI 为空而悄悄换一批 SPU。
5. **查证详情并判断。**进入选中 SPU 的盈利详情，或继续观察；运营判断和策略执行留在既有业务流程。

页面仅需条件/日期、对比列表、范围统计和详情入口。主要阅读层放两期盈利指标，订单/消耗、事实标注与限制紧邻展示；重点标注采用醒目文字和视觉强调，不只依赖颜色，不新增告警区域或规则配置页。

## 5. 功能规格

### 5.1 R-001：选择并确认范围

| 输入 | 规则与默认 |
| --- | --- |
| 店铺 | 必选，只能查询有权限的店铺；无可用店铺时说明原因，不自动换店 |
| SPU | 默认持续运营范围；可用现有精确查询，最多 100 个正整数内部编号；非法输入保留并提示，不退回整店 |
| 活动范围 | 以截至日近 7 天活动确定同一批 SPU，默认排除既无订单也无广告消耗的记录。普通对比样本沿用累计至少 3 单的排除建议，但近 7 天无单且有广告费的记录作为例外保留，不受累计小样本条件隐藏；累计只指库内可用历史。显示已应用条件，精确调查可绕过活动排除但不隐藏数据限制 |
| 窗口 | 默认 7 天，辅助选项 3 天；不提供 1 天或全部窗口。切换时保持店铺、SPU 范围和截至日 |
| 截至日 | 采用店铺当地日，默认取最新可用日；按完整日统计，不选尚未结束的当天。后台给出该店铺实际可查上限，日期控件禁止选择更晚日期，手输或链接绕过也须校验拒绝；允许选择上限以内的历史日期，不静默换日期返回结果 |

设截至日为 `A`，两端包含：

| 窗口 | 本期 | 上期 |
| --- | --- | --- |
| 7 天 | A−6 至 A | A−13 至 A−7 |
| 3 天 | A−2 至 A | A−5 至 A−3 |

例：A＝2026-10-06，7 天对比 9 月 30 日—10 月 6 日与 9 月 23—29 日；3 天对比 10 月 4—6 日与 10 月 1—3 日。两期不重叠，不用 UTC 日替代店铺当地日。

| 验收 | 可观察结果 |
| --- | --- |
| AC-001（R-001） | 首次进入默认 7 天、截至日为最新可用日；切换 3 天后准确回显两段日期，不混入 1 天或全部窗口 |
| AC-002（R-001） | 精确查询活动条件之外、但有可用数据的 SPU 时仍可查证；说明活动条件不生效及数据限制 |
| AC-003（R-001） | 最新可用日期为 10 月 3 日时，日历不能选 10 月 4 日以后；手输或链接绕过也校验失败并说明上限，不静默返回 10 月 3 日。非法 SPU/窗口仍保留输入并提示修正 |
| AC-004（R-001） | 改条件回第一页、关闭旧明细；合法查询条件可从链接恢复，不携带凭证；切换窗口不悄悄删掉少样本 SPU |

### 5.2 R-002：看清两项指标变化

每个 SPU 在选中窗口只展示一条结果，分别呈现本期/上期 ROI、净利润、差额和方向。单位清楚：净利润、消耗按现有 CNY 口径，ROI 为比率；不混用广告平台的广告归因 ROI。

- ROI 由周期累计金额按统一口径计算，不能平均日 ROI；净利润按周期聚合。
- 差额为本期减上期。仅上期大于 0 且两期有值时展示百分比；上期为 0、负数或缺失时为“—”，保留可计算的差额。
- ROI 可计算时，正数、零、负数均正常展示；负数不等于不可计算，也不因“无单但有广告费”强制隐藏 ROI。只有不可计算或必要数据缺失才显示“—”及具体原因，不拿负数、真实零值或缺失相互替代。
- 净利润按统一口径的实际值展示，包括负数，不人为置负或置零；ROI 无值时仍保留可用的净利润、订单数和消耗。
- 含未结算平台费估算时说明；历史数值可能随已确认退款、当前成本或汇率更新，不能称为固定的最终会计利润。
- 箭头、差额、百分比是展示值，不形成告警、资格判定或业务总计，也不改变查询范围。权威盈利计算遵循[开发契约](../business/spu-profitability.md)。

| 验收 | 可观察结果 |
| --- | --- |
| AC-005（R-002） | ROI 从 2 到 2.5、净利润从 100 到 80 CNY 时，分别显示 +0.5/+25% 与 −20 CNY/−20%，不合成一个好坏结论 |
| AC-006（R-002） | 可计算 ROI 从 −0.5 到 −0.2 时两期原值及 +0.3 差额正常展示；上期为 0 或负数时只将百分比显示为“—”，不隐藏 ROI 原值 |
| AC-007（R-002） | ROI 确实不可计算或缺少必要数据时显示“—”及原因，实际净利润/订单/消耗仍保留；可计算的 0、负 ROI 与缺失能区分 |
| AC-008（R-002） | 改变展示舍入不改变 SPU 范围、订单/SPU 统计或产生新的判定标签；能查到日期、单位和估值说明 |

### 5.3 R-003：重点标注无单投放，展示判断依据

两期订单数、广告消耗与盈利原值一起读。**某一期实际订单数为 0 且广告消耗大于 0 时，重点标注“无单但有广告费”**，明确对应本期或上期；7 天、3 天分别依各自日期判断，不把上期标记冒充本期状态。

- 无单投放记录保留在分析范围及统计中，不因没有订单、样本少或 ROI 无值而隐藏。重点展示实际净利润、广告费和零订单数；ROI 按 R-002 展示，可计算的负数也不例外。
- 这是已发生事实的醒目说明，不是告警等级、阈值配置或停投建议。后台决定范围和事实标记，前端只呈现；不能用缺失订单数据冒充真实零单，也不能靠显示舍入决定标记。
- 累计至少 3 单不等于两期样本充足；不新增每期最少订单、消耗或降幅的告警门槛。

3 天更易受少量订单、投放节奏及不同星期组合影响；7 天覆盖完整星期，但也不保证数据充分。两种窗口相反时保留原值、日期和方向，不自动称为误报、恢复或持续恶化。

| 验收 | 可观察结果 |
| --- | --- |
| AC-009（R-003） | 本期订单 0、广告费 100 CNY、实际净利润 −100 CNY 的记录仍展示，含累计不足 3 单的无单投放记录；醒目标注本期“无单但有广告费”，显示实际利润/消耗，ROI 能算则显示、不能算才显示“—” |
| AC-010（R-003） | 只有上期无单投放时，标注明确属于上期；单纯 ROI/净利润为负、有订单或订单数据缺失时，不误标为“无单但有广告费” |
| AC-011（R-003） | 查看 3 天时有短期波动说明；无法确认实际零单或消耗时说明数据限制，不以缺失冒充零，也不替运营决定加投/停投 |
| AC-012（R-003） | 3 天与 7 天方向相反时分别如实展示；不存在严重程度筛选、历史确认升级或加投/停投命令 |

### 5.4 R-004：说明统计范围

【方案建议】仅保留分析 SPU 数及选中窗口的本期/上期订单数，不保留告警/严重告警数量。SPU 按完整分析范围去重，订单跨 SPU 全局去重；不得相加行级订单数或把当前页当成全范围。

翻页不改变范围统计；窗口改变则按新的两段日期统计。没有可用统计显示“—”及原因，不伪造全 0。

### 5.6 R-006：数据时间与失败恢复

【已确认事实】数据没有更新时允许查看已有旧结果，醒目显示实际数据日期和“数据未更新”，不能用读取/计算时间冒充数据更新时间。默认截至日及可选上限停留在最新可用日；未更新的更晚日期不能选择或通过请求绕过，已有历史日期仍可查询。

最新可用日期由后台结合本页必要数据的可用状态统一确定，按店铺当地日返回；不能只拿某一来源最新一条记录的日期就声称所有数据齐全，也不要求全部订单已结算才可查看。日期上限的来源与校验是研发验证事项，不再等待新的产品决策。

刷新只是重新读取，不承诺触发同步或重算。新条件加载或失败时，旧列表、统计、明细不能冒充新条件结果；没有任何可用结果则说明不可用，不能伪造历史结果。无匹配、真实零值、ROI 无值、事实缺失、服务错误分别说明，服务错误提供请求编号。权限沿用现有只读访问，旧告警任务启用状态不是新增的产品开关。
