# 素材包实施计划

目标是在公共资产库中维护一份有名称的视频分组。运营可勾选已有视频建包、加入已有包或继续上传。数字人档案可关联已有包，也可新建后立即关联。两处看到同一份包。

基线为 `2435049d2900151cb7f223b4483c240a58384ae6`，任务分支为 `codex/media-packs`。范围依据为 2026-11-08 用户确认的交互和可点击原型。沿用 [媒体资产方案](../design/media-asset-library.md)、[前端规范](../guides/frontend-development.md) 和 [测试规范](../guides/agent-testing.md)。既有资产接口无法表达共享的具名视频组，因此需要增量数据库和应用变更。

在现有 media 模块实现。SQLAlchemy 和 PostgreSQL 管理分组、成员及档案关联，MinIO 仍以资产 ID 保存原视频。前端复用 React、HeroUI、应用骨架、资产查询和预签名上传。既有单条关联继续可读和维护，不自动创建分组。视频生成的参考素材同时覆盖原有直接关联和包内视频，按资产 ID 去重。包成员和档案关联只保存引用。仍被任何包引用的资产禁止全局删除。

TDD Route 为 off / skipped。用户授权原型后直接开发，仓库无测试先行要求。持久化、权限、并发、上传重试及跨页共享行为有专项回归。

1. 在 `alembic/versions/0076_media_packs.py`、`tts_erp_v2/db/models/media.py` 和 `tts_erp_v2/media/packs.py` 增加素材包和两种关联。建包与首次关联同事务提交，成员增量写入可重试。只接纳已入库的视频。新增关联与全局删除使用相同资产行锁。
2. 在 media API 增加包列表、详情、创建、添加/移出视频和档案关联/解除接口。资产接口复用分页和预览，并展示包引用。RunningHub 复用同一档案参考素材范围。API 保留默认的直接关联读取契约。
3. 在资产管理加入素材包视图和视频勾选入口。在数字人档案加入素材包区，复用包详情、组包与上传编辑器。多文件按已有上传协议确认入库，重试保留已完成的资产 ID。离开或取消保留已确认入库的文件。
4. 更新媒体设计和外部接口契约。用隔离 API 测试证明类型、事务、幂等及保留原文件，用实际浏览器走通组包、补传、跨页关联和解除。刷新测试模板后，在精确同步的已提交候选运行 `bash scripts/test_baseline.sh --scope auto --base "$target_sha" --scenario page-assets`。主线集成按仓库锁和精确提交验证流程执行。
