# 其他页面空白与布局密度修复

用户要求继续检查并修复其他页面中类似 SPU 筛选区的大量留空。本轮从 `origin/master 4b1609cb` 开始，使用已有独立工作树、`codex/compact-admin-page-layouts` 分支；只修改前端布局及相关验证/记录。采用现有 HeroUI 组件和页面布局，不新增依赖、权限或业务计算，不把空数据态当作布局故障。

## 范围与执行

1. 按权威 PAGES 目录检查其余 13 个业务页面，已保存本机 2560px 首屏截图和面板尺寸。SPU 两页保留上一轮结果，登录页仅检查其现有独立表单布局。
2. 复用紧凑横向工具条，收束分类/范围/刷新等相邻操作；合并采购页多层筛选，整理广告和对比页的字段宽度及操作位置。
3. 统计图表与完整每日数据在宽屏并列，分布卡片不强制等高；视频上传、公开配置和轨道按响应式布局组织，完整内容和确认流程保留。控制台快捷入口收紧。其他页面只调整有证据的间距或过宽控件。
4. 运行类型检查、相关隔离组件与浏览器验证；最后完整 baseline 只执行一次，使用已保存的 149 项既有失败清单逐 ID 对照，新增差异仅复验最小范围，不改写基线。
5. 提交推送、按已有用户授权整合 master 并更新本机同版本完整前端包；在 2560/1440/375 检查实际页面和当前编译候选。全部读写、确认、角色、未知结果读回和冷却状态仍由原 handler 管理。

## 验收边界

筛选与相关按钮就近，短字段不无谓占满整行，宽屏可并排的独立区域充分利用宽度，窄屏自然换行且不产生整页溢出。不通过隐藏业务信息、删除表格列、缩小字号或减小点击区域实现密度。真实页面仅只读浏览，不触发创建、提交、发布、授权或删除。

证据目录：本机会话可视化目录下 `layout-density-2026-11-02/`。运行包为 `build-a592f5d66eabe7c68db6` 的截图属于修复前证据；后续记录实际候选版本与结果，不能将旧截图算作修复后验收。
