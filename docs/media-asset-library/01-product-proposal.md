## 1. 决策摘要

**唯一目标：让运营在全局媒体资产库里维护「有名字的视频分组」，并让数字人档案能引用这些包——同一个包被多个档案复用，两处看到同一份内容。**

- **看谁：**在资产管理页维护公共素材包（勾选库内视频建包、加/移出包内视频），在数字人档案页关联已有包或新建包后立即关联。
- **看什么：**素材包 = 名称 + 一组视频（资产 ID 引用）。包本身不存视频字节，只存引用；同一个包可被多个档案关联。
- **怎么做：**建包与首次关联档案在**同一事务**内提交；包成员增量写入可重试；已入库视频才能入包。
- **边界：**移出视频保留原素材，解除档案关联保留包，归档档案保留关联。**仍被任何包引用的资产禁止全局删除**（连同未删除数字人的直接引用一起构成删除阻塞）。
- **复用：**数字人主入口从「直接关联素材」扩到「素材包」，原有直接关联继续可读可维护、不自动转成包。

**为什么现在做这一版：**素材包的表、API、页面已在 master，但产品口径只散落在技术方案和实施计划里，且缺少与代码现状对齐的验收标准。这份 PRD 把「代码现在实际是什么样」和「产品承诺什么」逐条对齐，缺口在 §5 交由开发与测试确认。

**本版不是新功能开发**——它是对已落地实现的产品化收口。

### 2.2 素材包的数据契约（已落地，供验收对照）

| 表 | 含义 | 关键约束 |
| --- | --- | --- |
| `media.media_packs` | 一个具名视频分组 | `creation_token` UUID 唯一（幂等建包）；`name` 非空；`ON DELETE CASCADE` 挂成员与关联 |
| `media.media_pack_videos` | 包 ↔ 视频多对多 | 复合主键 `(pack_id, asset_id)`；`asset_id` 外键指向 `media.media_assets`；建索引 `ix_media_pack_videos_asset`（按资产反查包） |
| `media.digital_human_packs` | 档案 ↔ 包多对多 | 复合主键 `(digital_human_id, pack_id)`；建索引 `ix_digital_human_packs_pack`（按包反查档案） |

三张表均挂 `public.fn_touch_updated_at()` BEFORE UPDATE 触发器（仓库既有约定）。迁移 `downgrade` 在 `media_packs` 非空时**拒绝降级**——这是有意的防误删设计。

### 2.3 接口清单（已落地，供验收对照）

| 方法与路径 | 作用 | 最低角色 |
| --- | --- | --- |
| `GET /v2/media/packs` | 包列表（含关联档案数、引用视频数） | readonly |
| `GET /v2/media/packs/{pack_id}` | 包详情 | readonly |
| `POST /v2/media/packs` | 建包（可同时建包 + 关联档案 + 加视频，同事务） | readwrite |
| `POST /v2/media/packs/{pack_id}/videos` | 向包添加视频 | readwrite |
| `DELETE /v2/media/packs/{pack_id}/videos/{asset_id}` | 从包移出视频 | readwrite |
| `POST /v2/media/digital-humans/{id}/packs` | 档案关联包 | readwrite |
| `DELETE /v2/media/digital-humans/{id}/packs/{pack_id}` | 档案解除包关联 | readwrite |

**跨接口的一致性契约**（已落地，验收时按此核对）：

- 资产详情 `usedByPacks` 列出该资产被哪些包引用。
- 资产列表支持 `packId`（只看某包内）与 `excludePackId`（排除某包）过滤。
- 数字人详情支持 `includePackVideos`，RunningHub 参考素材走同一开关。
- 引用中的资产 `DELETE` 返回 `409 ASSET_IN_USE`，且**不调用对象存储删除**、不软删记录。

## 3. 明确不做什么

1. **不新增 AI 生成能力。** 数字人只是档案容器；生成能力在 RunningHub 侧，本库只提供参考素材。
2. **不与 TikTok 视频发布流水线联动。** `publishing.video_publish_tasks` 仍独立可用。
3. **不做服务端缩略图 / 转码。** 本机无 ffmpeg；预览用浏览器原生 `<video>` 播放预签名 GET URL。
4. **不做资产去重、版本管理、CDN、配额。**
5. **不做包名唯一性约束、不做包的合并/拆分/重命名。** 本版包的单位是「加视频 / 移视频 / 关联 / 解除关联」。
6. **不把既有直接关联自动转成包。** 迁移不重写既有数据，直接关联与包关联长期并存。
7. **不删除快照以外的历史数据。** 无真实数据清理任务；本版不涉及任何生产数据删除。
8. **不在本 PRD 里定义盈利口径。** 盈利/ROI/费率口径单点定义在 `docs/business/spu-profitability.md`，本文只引用不重定义。

## 4. 验收标准

验收在**隔离环境**执行（`bash scripts/test_isolated.sh ...`），禁止直连生产形状库。媒体库的写入验收全部用 `TEST_` 前缀数据。

### 4.1 素材包核心契约

| # | 验收项 | 通过判据 |
| --- | --- | --- |
| AC-MP-01 | 建包与首次关联档案的原子性 | 建包 + 加视频 + 关联档案在同一事务内提交；任一步失败则三者都不落库，无半成品包 |
| AC-MP-02 | 建包幂等 | 同一 `creation_token` 重复请求返回**同一个包**，不产生第二个包、不重复加视频 |
| AC-MP-03 | 只接纳已入库视频 | 传入 `awaiting_upload` 或 `failed` 状态的资产 ID 被拒绝，已就绪票据可再次确认后入包 |
| AC-MP-04 | 成员增量可重试 | 重复添加同一视频不产生重复行；重试不丢已成功的成员 |
| AC-MP-05 | 包跨档案复用 | 一个包被两个不同档案关联，两处读到同一份包内容；移出视频保留原素材 |
| AC-MP-06 | 解除关联的保留语义 | 解除档案关联保留包；归档档案保留关联；从包移出视频保留资产本身 |
| AC-MP-07 | **删除阻塞三来源** | 资产被①数字人直接关联 ②数字人形象照 ③任一包成员 引用时，`DELETE` 返回 `409 ASSET_IN_USE`，记录不软删、存储字节不删；**归档档案的引用同样阻塞**（软删的档案不阻塞） |
| AC-MP-08 | 参考素材去重 | 同一资产既被直接关联又被包引用时，RunningHub 参考素材中**只出现一次**；去重**保序**（直接关联在前，包内按添加顺序追加） |
| AC-MP-09 | 行锁互斥 | 资产行锁在「新增关联」与「全局删除」两条路径上互斥；并发下不出现「删除成功但关联已存在」或反之 |
| AC-MP-10 | 权限门槛 | readonly 会话对全部写端点 403；`GET` 在 readonly 下可访问 |

### 4.2 既有媒体库契约（本次回归不得回退）

| # | 验收项 | 通过判据 |
| --- | --- | --- |
| AC-ML-01 | 上传协议 | 预签名直传；100% 传输与确认入库**分开反馈**；确认失败重试同一票据，标签与名称保留 |
| AC-ML-02 | 删除保护（既有） | 引用中资产 UI/API 均禁止删除并显示引用者（含归档）；全部解除后才可删除；确认期间新增引用由事务拒绝 |
