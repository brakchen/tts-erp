# 用户管理

## 目的
管理登录账号、角色与会话，按职责分配页面和 API 档位。这是建号的唯一工作台入口。

## 角色
预置角色中仅系统管理员拥有本页（`page:users`）。维护操作需 admin。禁止禁用 / 降权自己，禁止去掉最后一个 admin。

## 主流程
- 用户页签：按用户名 / 显示名搜索，按启用 / 停用筛选；新建用户；编辑显示名；分配角色；重置密码（将吊销该用户全部会话，须线下告知）；启用 / 停用（停用吊销全部会话）；查看并吊销单个或全部会话。
- 角色权限页签：查看角色目录；新建 / 编辑 / 删除自定义角色（勾选可访问页面、设置 API 档位）。内置角色不可删除；内置 admin 不可编辑；其余内置角色不可改 API 档位。仍被引用的角色不能删除。

## 关键字段
- 用户表：用户名、显示名、状态、角色、最后登录、活跃会话数、操作。
- 角色表：代码、名称、描述、API 档位、类型、权限点、用户数。
- 会话表：会话 ID、创建 / 到期、IP、User-Agent、最后活跃、吊销。
- 密码策略：至少 6 位，须含大小写字母和数字（服务端最终校验）。用户名创建后不可改。

## 空态 / 错态
- 当前仅浏览时提示需要 admin。提交未完成须查询公开状态后再决定是否手动重试。

## 验收要点
- 登录页无注册入口。预置运营、只读分析看不到本页。
- 工作台没有给当前登录用户改自己密码的入口（管理员可重置他人密码）。

## 缺口
见总册第 1 条。权限设计文档中的页面清单已落后于 18 页注册表。

## 现状附录
