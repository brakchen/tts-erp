# 店铺注册

## 目的
把店铺接入本地分析：插件发现或手工补录 → 配置 Partner App → 获取授权链接 → 卖家完成授权后，官方同步才按已授权店扇出。

## 角色
系统管理员、运营可进入。只读可看列表和说明，不能配置或生成链接。生成链接需要 readwrite 以及本页权限。

## 主流程
1. 筛选并核对企业已发现或补录的店铺（名称、区域、开店日期、插件是否在上报）。
2. 手工补录（店铺 ID 必填；名称和区域保存后只读）或编辑开店日期（留空保存可清除）。
3. 为当前店配置 App：Service ID，成对填写 App Key / Secret；Secret 不回显。
4. 获取一次性授权链接，用目标店卖家账号打开；回调后更新授权状态。
5. 之后 `tiktok.*` 与 token 续期按已授权店扇出。插件上报可以早于授权。未授权店铺仅在本页展示。

## 关键字段 / 筛选 / 操作
- 筛选：名称 / ID / 编码，发现来源（Ads 插件 / Monitor 插件），App 配置（已配置 / 未配置），OAuth（未授权 / 已授权 / 需重新授权 / 待确认）。
- 表列：店铺、区域 / 开店日期、插件资料同步、App 配置、OAuth 授权、操作（编辑信息 / 配置 App / 获取授权链接）。
- 页头：刷新店铺、手工补录。

## 空态 / 错态
- 没有符合条件的店铺：提示绑定插件后会自动登记，也可手工补录。
- 操作冷却、放弃未保存修改的确认、授权链接过期须重新获取。

## 验收要点
- `/v2/oauth/tiktok/onboard` 不能替代本页完成授权。
- 官方同步依赖授权；插件发现不依赖授权。

## 缺口
见总册：授权说明页只是跳板；部分旧文档把店授权误写成必须 admin（实际 readwrite 即可）。

## 现状附录
- 路由：`/v2/pages/shops`。回调：`/v2/oauth/tiktok/callback`。
