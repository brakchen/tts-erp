# 利润劣化告警

## 目的
对同一 SPU 对比近期窗口与上一等长窗口的 ROI、净利润、订单数、广告消耗，帮助运营看清变化后再人工判断。

## 角色
系统管理员、运营可进入。预置「只读分析」**默认不能进入**。本页无写操作。

## 主流程
1. 选择店铺、截至日（不超过最新可用的店铺当地完整日）、比较窗口（7 天主参考或 3 天观察近期变化）、活动范围或全部本店 / 精确内部编号。
2. 应用筛选后查看完整分析范围统计与对比表。
3. 展开单 SPU 明细，需要时跳到对应经营日期的 SPU ROI。勿把 3 天涨跌单独当成持续改善或恶化。

## 关键字段 / 筛选 / 操作
- 筛选：店铺、精确 SPU 内部编号、比较窗口、截至日、活动范围（固定近 7 天活动并保留无单投放 / 全部本店）、每页条数、应用 / 重置 / 刷新。
- 统计：分析 SPU 数、本期 / 上期订单数。
- 对比列：SPU / 查证、ROI、净利润（CNY）、订单数、广告消耗（CNY）、事实与限制。展示上期、本期及变化方向。
- 可计算的 ROI（含负数）正常展示；不可计算显示「—」。无单但仍有广告费的记录保留并重点标注。

## 空态 / 错态
- 当前条件无匹配：提示调整范围，不代表全店正常或无风险。
- 日期超过最新可用日须修正。输入未应用时，下方只显示已应用范围。
- 读取失败进入冷却，结束后需手动重试。

## 验收要点
- **不做**阈值告警、告警推送、严重程度筛选或自动投放建议。
- 旧的每日评估写告警表任务已停调度；本页直接读盈利结果做对比，不是自动告警中心。

## 缺口
- 菜单名称含「告警」，产品方案与页面文案均明确不做告警系统，存在命名落差。
- 预置只读角色默认无本页，与「分析页应对齐」的直觉可能不一致（见总册缺口第 4 条）。
