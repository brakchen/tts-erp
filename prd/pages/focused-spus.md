# 重点关注 SPU

## 目的
按店铺维护一份持久化的关注清单，并用与 SPU ROI 相同的 v10 盈利口径查看这些商品的经营结果。不替换 SPU ROI 页。

## 角色
系统管理员、运营、只读分析可进入。浏览关注清单与盈利为只读；新增 / 移除关注需要 readwrite。

## 主流程
1. 先选择店铺，系统读取该店完整关注清单（按店隔离）。
2. 按 SPU ID / 标题搜索并添加，或移除已关注标签；readwrite 下实时保存。
3. 在同一套经营范围工具条上选择日期、预测样本等，查看大盘与明细。
4. 点击商品行下钻利润构成、订单·物流、结算、售后、广告证据。
5. 清单为空时，范围仍是关注清单，不会回退成全店。

## 关键字段 / 筛选 / 操作
- 经营范围：店铺、起始日 / 截止日、快捷日期（昨天 / 近 7 天 / 近 30 天 / 本月 / 不限）、预测样本 30 或 90 天、临时佣金费率、「含无活动 SPU」。
- 关注编辑：搜索、已关注标签、移除。源码一次最多添加 500 个（与 ROI 页临时选择上限 100 不同）。
- 经营概览：当前 vs 预计最终的 ROI 与经营指标；数据更新条；计算依据。
- 明细列：商品（含缺成本 / 高退款 / 亏损等标记）、广告消耗、广告系统实际 / 保本 ROI、有效销售、总单量、有效单量、取消率、全损率、净利润。
- **本页不展示**销售 / 采购价格统计和价格列（源码对 focused 配置为隐藏）。
- 分页 50 / 100 / 200。排序与分页不改大盘。
- 口径：金额 CNY；成本优先级 人工价 > 妙手货源价 > 40 CNY 兜底；无汇率快照则整页不可算。

## 空态 / 错态
- 尚未关注 SPU：提示在上方搜索并添加，当前范围仍为关注清单。
- 店铺不可用或未选择：强制先选店。
- 保存未确认：保留原选择，需重新读取关注事实后再决定。
- 只读：提示修改需要 readwrite。

## 验收要点
- 刷新或重新登录后关注关系仍在。
- 空关注集合返回空结果，不得回退整店。
- 盈利只引用服务端 v10 结果，前端不重算。
- 与 SPU ROI 是两个入口，原型和菜单须分开呈现。

## 缺口
- 设计曾写两页交互 UI 一致，实现上本页隐藏价格统计。待确认是否有意。
- 盘点曾写关注最多 100 个，源码上限为 500。以源码为准。
- 预置只读可以进入本页，但不能改清单。
- 不提供跨店全局关注、分组或告警通知（有意非目标）。

## 现状附录
- 路由：`/v2/pages/focused-spus`；清单 `GET/PATCH /v2/reporting/focused-spus/{shopPk}`；盈利查询带 `scope=focused`。
