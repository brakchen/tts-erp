## 1. 背景

运营团队同时面对 TikTok Shop 销售、广告投放、售后与结算、妙手采购价和内容素材。这些事实分散在平台后台、浏览器插件和采购工具里，缺少一个以商品（SPU）为中心、口径统一的本地分析工作台。

tts-erp 把 TikTok Shop、妙手采购、Chrome 扩展采集和汇率快照写入本地 PostgreSQL，提供运营页面和 SPU 盈利分析。它是**读侧分析系统**：允许写入同步数据、配置和人工成本，但不提供修改真实 TikTok 店铺订单、退货、取消或发货状态的能力。

运营入口只有一套工作台：`/v2/pages/*`。形态是服务端输出 HTML 壳与导航数据，再由 React 水合；侧边栏 18 个页面的文案、分组和可见性由服务端页面注册表按权限下发。点侧栏是整页跳转，不是浏览器内单页路由。没有第二套仍在服务的运营站点。

## 2. 产品定位

面向 TikTok Shop 卖家团队的**本地分析 ERP / 运营工作台**：

- 看清店铺覆盖、同步健康和数据新鲜度
- 按 v10 口径计算并展示 SPU 及大盘的净收入、成本、广告、退款 / 全损 / 取消、净利润和 ROI
- 维护人工采购成本、店铺授权和运行配置，保证分析依据完整
- 为采集插件维护拦截规则，并抽查记录与统计
- 管理内容资产，经换装生成和视频发布把素材送到 TikTok 内容侧（与改订单状态无关）

品牌呈现为「tts / erp」运营工作台。生产公网常见前缀为 `/tts`，本机直连无此前缀。

## 3. 目标

1. 让运营用工作账号登录后，在同一套工作台完成日常看数、补成本和店铺接入，而不必在多个后台之间对口径。
2. 以服务端 v10 盈利结果为准看当前事实和预计最终大盘，并能下钻到订单、物流、结算、售后和广告证据。
3. 把店铺从「插件发现或手工补录」推进到「配置 App 并完成授权」，使官方同步按已授权店扇出。
4. 把同步任务、广告日事实和拦截采集的健康度放到可观察的页面上。
5. 在授权范围内支持内容生产（素材库、数字人、换装成片）和视频发布核对。

上述目标对应的能力均已实现。优先级见第 8 节，表示产品建设优先级，不是「尚未开发」。

## 4. 目标用户与预置角色

| 预置角色 | 显示名 | API 档位 | 默认可访问页面 | 典型职责 |
| --- | --- | --- | --- | --- |
| admin | 系统管理员 | admin | 全部 18 个页面 | 账号与角色、周期调度、枚举维护、高风险配置 |
| operator | 运营 | readwrite | 除「用户管理」「视频发布」外的全部页面 | 看盈利、补成本、店铺授权、同步触发、内容资产 |
| viewer | 只读分析 | readonly | **仅**：控制台、重点关注 SPU、SPU ROI、广告日明细、拦截统计 | 看经营结果，不进配置、采购、劣化对比、内容资产等页 |

管理员可另建自定义角色（自选页面 + API 档位）。有效权限是用户所挂角色的并集。

预置「只读分析」默认**看不到**利润劣化告警、采购工作台、店铺注册、枚举映射、运行配置、定时任务、拦截配置 / 记录，以及内容资产与视频发布。若业务需要，只能改角色授权，不是系统自动放开。

另外还有插件、脚本使用的 **API key**（只有 API 档位，没有页面权限）。签发、轮换、吊销目前走命令行 `api_keys.py`，工作台没有对应页面，完整密钥只在创建或轮换时打印一次。浏览器工作台登录是**用户名 + 密码**，不是 API key 换 cookie。根目录 README 仍写旧登录方式，属于文档落后，见第 10 节。

## 5. 用户故事

### 5.1 作为只读分析，我想……

- 作为只读分析，我想用分配的账号登录工作台，以便查看被授权的经营页面。
- 作为只读分析，我想在控制台看到待录成本、SPU 数、店铺数和同步健康，以便判断数据是否可用。
- 作为只读分析，我想在 SPU ROI 或重点关注页按店铺和日期查看 v10 盈利大盘与明细，以便评估商品表现。
- 作为只读分析，我想打开广告日明细并按账户、日期筛选，以便核对投放事实（汇总为 USD）。
- 作为只读分析，我想查看拦截统计，以便了解采集是否正常。
- 作为只读分析，我想浏览某店已关注的 SPU，但不修改清单，以便只看重点商品。

### 5.2 作为运营，我想……

- 作为运营，我想在采购工作台按店铺补齐人工成本，以便盈利计算优先使用人工价。
- 作为运营，我想把新店从发现或手工补录推进到配置 App 并获取授权链接，以便官方同步开始按店扇出。
- 作为运营，我想维护重点关注清单，以便固定范围看这些商品的盈利。
- 作为运营，我想在利润劣化页对比 7 天 / 3 天两期表现，以便判断近期变化后再跳到 ROI 详情（不做自动告警）。
- 作为运营，我想查看并手动触发同步任务，以便在数据落后时补跑；我不需要也不能启停周期调度。
- 作为运营，我想维护拦截规则并查阅记录，以便插件按规则采集。
- 作为运营，我想管理素材、数字人和换装批次，以便在确认费用后生成成片。
- 作为运营，我想在运行配置里编辑草稿并确认发布，以便监控等业务读取生效版本。

### 5.3 作为系统管理员，我想……

- 作为系统管理员，我想创建账号、分配角色、重置密码并吊销会话，以便团队按职责访问，且登录页不开放自助注册。
- 作为系统管理员，我想启停同步任务的周期调度，以便在必要时暂停自动跑批，同时保留手动触发。
- 作为系统管理员，我想维护枚举映射的中文标签，以便页面使用统一语言。
- 作为系统管理员，我想被授权后使用视频发布页，把视频发到 TikTok 内容侧并核对结果。
- 作为系统管理员，我想检查和保存 RunningHub 工作流与账户配置，以便换装任务可向云端发起。

## 6. 功能范围

### 6.1 系统已提供

- 用户名 + 密码登录、会话、退出；管理员在用户管理中建号、分配角色、重置他人密码、管理会话。
- 控制台：按权限显示快速导航、覆盖摘要、店铺精简表、API 健康与同步状态。
- SPU ROI 与重点关注 SPU：共用盈利模块、两个独立入口；服务端按 v10 计算，前端只展示。
- 利润劣化告警页：对同一 SPU 做 7 天 / 3 天两期对比（ROI、净利润、订单数、广告消耗），可跳到 ROI 详情。
- 广告日明细：筛选、分页、全部匹配行的 USD 汇总与行详情。
- 采购工作台：按店铺维护人工成本草稿、逐行确认提交、查看提交历史。
- 店铺注册：插件发现或手工补录、编辑开店日期、配置 App、获取一次性授权链接。
- 枚举映射、运行配置（草稿 / 发布 / 历史 / 凭证）、定时任务（查看、手动触发、管理员启停周期）。
- 拦截配置 / 记录 / 统计。
- 内容资产：素材库与素材包、数字人档案、换装视频批次。
- 视频发布：设备队列、上传入队、状态刷新、允许范围内的确认 / 重试 / 诊断。
- 后台同步 worker 与 Chrome 插件接入（广告、订单域、拦截、监控）；妙手数据由进程内同步任务拉取。

### 6.2 明确不做（产品边界，不是缺陷）

- **不提供**修改真实 TikTok 店铺订单、退货、取消或发货状态的写端点。
- 不把工作台做成「订单中心 / 售后中心 / 结算中心 / 汇率台」。订单、履约、售后、结算只出现在盈利下钻和只读 API 中。
- 登录页不提供自助注册、找回密码或第三方登录 / MFA。
- 工作台不提供 API key 的签发、轮换、吊销界面；插件和脚本所需密钥目前通过命令行管理，不在工作台范围内。
- 盈利页不在前端重算公式或业务阈值；无汇率快照时整页不可算，不用固定汇率凑数。
- 重点关注不提供跨店全局清单，也不在当前版本提供关注分组、负责人或告警通知。
- 利润劣化页**不做**阈值告警、告警推送、严重程度筛选、历史确认升级或自动加投 / 停投建议。
- 视频发布首版不做批量 / 定时发布、Shop Open API 发帖、提交后取消或解锁参数、自动重试。
- 妙手没有对运营开放的 HTTP 业务界面。
- `docs/plans/` 下尚未落地的方案（例如部分工作区或插件架构清理设想）**不计入**现有功能。

### 6.3 边界外但代码里确实存在的写行为（需单独认知）

这些不是「改 TikTok 店铺订单状态」，但会对外部系统产生作用，产品上必须写清：

1. **广告监控插件（monitor）** 可在卖家已登录的 Seller Center 会话里，按规则自动关闭广告计划，并发送飞书通知。这不经过 ERP 的 TikTok 写 API。
2. **视频发布** 经外部设备和发布 worker，把视频发到 TikTok **内容侧**。
3. **换装视频（RunningHub）** 会向第三方云端发起**计费**生成任务，启动前需要明确确认。

### 6.4 本方案包的默认范围

本包的需求文档和原型，默认范围是**运营工作台**（`/v2/pages/*` 的 18 个菜单页，以及登录、授权说明、授权结果等辅助页）。

五款 Chrome 插件（广告数据同步、订单数据同步、请求拦截、广告监控、妙手订单捕获）是已有的采集或执行能力，在总册和信息架构里作为附件说明，本包不为插件 Popup 或扩展设置单独写页面文档或原型。插件在工作台里已经露出的部分（例如拦截配置 / 记录 / 统计、广告日明细、店铺注册中的插件发现、运行配置对监控策略的承载）仍属于工作台范围。

后续技术方案默认按上述工作台范围编写；插件只作为已有采集能力附件说明，除非另行单独立项。

## 7. 模块说明（已实现）

### 7.1 登录与会话

运营用用户名 + 密码登录。成功后写入 HttpOnly 会话 cookie，默认进入运营页。顶栏显示显示名并提供退出登录。失败信息统一为「用户名或密码错误」。存在登录结果核对（查询当前会话，不自动当成登录成功）。改自己的密码仅有 API，工作台顶栏无入口。

### 7.2 总览：控制台

经营全局入口。按权限显示快速导航（采购、SPU ROI、店铺、拦截配置、运行配置、广告日明细）。数据摘要：待录成本 SPU 数、已跟踪 SPU 总数、已注册店铺数。店铺精简表。系统状态与同步任务表（约 60 秒刷新）。

### 7.3 经营分析：SPU 盈利（两个入口）

SPU ROI 与重点关注 SPU 共用同一前端模块和同一套 v10 口径，原型和需求里仍分成两个入口。

- 金额统一为 CNY。成本优先级：**人工价 > 妙手货源价 > 40 CNY/件兜底**。无可用汇率快照则整页不可算。
- 当前指标是所选窗口内截至计算时点已确认的事实；预计最终只出现在大盘，使用独立 30/90 天成熟样本，与经营日期分开。
- 搜索、排序、分页只改明细，不改大盘。精确 SPU 或关注集合属于业务范围，同时约束当前和预测大盘。
- 重点关注：按店铺持久化清单；readwrite 可增删，只读可浏览。源码一次添加上限为 500（临时精确选择上限为 100）。
- 重点关注页在实现上不展示价格统计与价格列（SPU ROI 页会展示），与「两页交互完全一致」的设计表述不完全相同，见缺口。
- 下钻包含利润构成、订单·物流、结算、售后、广告；订单明细最多 500 条。这些不是独立业务中心。

### 7.4 经营分析：利润劣化告警

页面名称带「告警」，实际是**两期对比页**。选择店铺、截至日、3 或 7 天窗口、活动范围（保留无单投放）或全部 / 指定 SPU，对比 ROI、净利润、订单数、广告消耗。无单但有广告费的记录会保留并标注。可展开明细并跳到对应经营日期的 SPU ROI。

旧的「每日评估器写告警表」定时任务已于 2026-11-09 从调度注册表撤下。本页直接读现有盈利结果，**不要理解为自动告警推送已上线**。

### 7.5 经营分析：广告日明细

浏览插件上报并落入本地的广告日事实。筛选店铺 Seller ID、广告账户、数据接口、日期、计划 / 商品 ID（部分匹配）。顶部汇总针对全部匹配行，不只是当前页；源币种 USD。会话分析未作为生产同步集合启用；today→daily 固化任务已停。

### 7.6 基础设置：采购、店铺、枚举、运行配置、定时任务、用户

- 采购工作台是盈利最高优先级成本来源的维护入口。
- 店铺上线路径：插件发现或手工补录 → 配 App → 取一次性授权链接 → 回调后官方同步才按店扇出。`/v2/oauth/tiktok/onboard` 只是说明跳板，不能在本页完成授权。
- 枚举映射把上游英文值译为中文标签。**写入实际要求 admin**（不是登记表上的 readwrite）。
- 运行配置提供版本化 JSON 与加密凭证。**打开页面要求 readwrite**。
- 定时任务展示当前注册的同步作业。**打开页面要求 readwrite**；手动触发 = readwrite；启停周期 = admin。旧利润日报任务仍在调度，但不是 v10 盈利真相源。已停用的 today→daily 与劣化评估任务不应再当成现行能力。
- 用户管理仅 admin（预置角色中仅系统管理员有该页）。

### 7.7 数据工具与内容资产

- 拦截配置 / 记录 / 统计为 Chrome 拦截插件服务。配置相关 API（含 GET、导出）需 readwrite。页面搜索框不会真正过滤。
- 视频发布把视频发到 TikTok 内容侧。预置运营角色默认不含此页。
- 资产管理、数字人、换装视频构成内容链路。换装会向 RunningHub 发起计费任务；工作流 / 账户类操作需 admin。

同步任务、插件种类和核心实体关系见信息架构文档，此处不展开接口设计。

## 9. 验收标准（总册）

1. 未登录访问需鉴权的工作台页面时，进入登录页；登录成功进入 `next` 或默认运营页。登录页无注册入口。
2. 侧栏只渲染当前用户拥有的页面权限；无权限直接打开对应路由应被拒绝（已登录无权限 ≠ 未登录）。
3. 预置只读分析只能进入控制台、重点关注、SPU ROI、广告日明细、拦截统计；写按钮不可用或请求被服务端拒绝。
4. 预置运营不能进入用户管理和视频发布，除非另行授权。
5. SPU 盈利金额为 CNY，口径说明指向 v10；无汇率快照时不能用固定汇率给出结果。
6. 大盘不受当前页搜索、排序、分页改变；关注或精确 SPU 范围同时约束当前与预测大盘。
7. 采购提交后的人工价在后续计算中优先于货源价和 40 CNY 兜底（计算当日口径，不把本文写成回溯改写历史窗口）。
8. 未授权店铺完成 App 配置和卖家授权之前，官方 `tiktok.*` 同步不按该店扇出；插件上报可以早于授权。
9. 授权说明页只引导去店铺注册台，不在本页生成授权链接。
10. 利润劣化页可完成 7/3 日对比，但不出现阈值告警列表或自动推送。
11. 工作台没有「订单中心 / 售后中心 / 结算中心」菜单。
12. 系统不暴露修改真实 TikTok 订单 / 退货 / 发货状态的写操作；监控关计划、视频内容发布、RunningHub 计费任务按各自页面规则工作。
13. 打开运行配置、定时任务要求 readwrite；手动触发同步为 readwrite，启停周期为 admin。
14. 枚举映射的增删改被非 admin 拒绝。

各页细项见 `pages/`。

## 10. 现状缺口

以下只客观描述现状，**不是改造承诺**。第 1–14 条对齐功能盘点第 5 节并有代码或文档证据；第 15 条及其后几条是对照源码补充的说明或待确认点。

1. **工作台没有「修改自己密码」的界面**。`POST /v2/auth/change-password` 已实现，顶栏只有显示名和退出登录。登录用户无法在页面里改密；管理员可以给别人重置密码。
2. **拦截配置页的「搜索」不会真正过滤**。页面提交 `search`，并写明接口未实现搜索；列表 API 只接受域名（精确匹配）、启停状态和分页。用户可能以为能搜 endpoint / 描述 / 标签。
3. **登录方式文档落后于代码**。根目录 `README.md` 仍写浏览器用 API key 换 cookie；实现和登录页已是用户名 + 密码。按 README 操作会误判登录方式。
4. **「只读分析」预置角色覆盖面窄，且与部分分析页不齐**。默认不含利润劣化、采购、店铺、拦截配置 / 记录等。发放该角色后对方进不了这些页，除非改授权。
5. **枚举映射「谁能改」的登记表与真实限制不一致**。`PAGE_MIN_WRITE_TIER` 写成 readwrite；页面文案和 `PUT/DELETE` 均要求 admin。只按登记表给运营写权限时，打开页面但保存会被拒绝。
6. **广告插件的「会话分析」未作为生产同步集合启用**。商品分析和变更日志在用；会话分析代码还在但已从启用集合移除。广告日明细和盈利中的广告事实不包含该未启用集合。
7. **广告「今日表固化到日表」的定时任务已停用**（约 2026-09-19）。广告浏览页读 `plugin.ad_daily`；不存在把「今天实时表」自动滚到日表的调度。日数据依赖插件现行的 T-1 同步路径。
8. **利润劣化「每日评估写告警表」已不再调度**。对比页改读盈利结果。旧评估模块和快照表仍留在代码库，但无读取方。用户不会收到基于旧评估器的自动告警写入，只能在对比页主动查询。页面对比功能本身是完整的，不是空壳。
9. **订单 / 履约 / 售后 / 结算没有独立运营列表页**。存在只读 API 与同步任务；这些事实出现在 SPU 盈利下钻里。不能按订单号在独立页面浏览全量订单或处理售后。
10. **汇率、旧版利润日报、成本快照、商品实时透传没有运营页**。相应 API 存在；盈利页会消费汇率快照。旧版利润日报仍在调度，但不等同于 SPU 盈利 v10。
11. **拦截插件的服务端地址在扩展内写死**。使用者通常只手动填 API Key，不能像广告 / 订单插件那样在 Popup 里改 ERP 地址；换环境需要改插件构建或另行发版。
12. **妙手订单捕获插件不接入 ERP**。只在本机保存最近记录并导出 JSON，不向 ERP 上传。ERP 侧妙手数据来自官方同步任务，不是这个插件。
13. **授权「控制台」页不能在本页完成授权**。`/v2/oauth/tiktok/onboard` 只做说明并跳转店铺注册台。书签若仍指向该地址，用户会发现只是跳板。
14. **部分管理模块文档仍写「整个 /v2/admin 都是 admin」**。实际店铺注册 / 更新和手动触发同步只要 readwrite，启停周期和限流等才是 admin。只看旧注释会把运营可做的事误判为必须管理员。
15. **工作台没有 API key 签发 / 轮换 / 吊销页面**。插件和脚本使用的密钥通过命令行 `api_keys.py`（`create` / `list` / `revoke` / `rotate`）管理；完整密钥只在创建或轮换时打印一次，库中只存哈希和前缀。这与「改自己的密码只有 API、工作台无入口」类似：密钥管理目前不在工作台范围内。本条只说明现状，不是改造承诺。

**对照源码补充（非盘点原 14 条，请产品再确认）：**

- 权限设计文档 `docs/design/user-account-authz-design.md` 的权限点清单和「运营含全部业务页（仅除用户管理）」已落后：代码中预置运营还不含视频发布，页面清单也已增至 18 项。
- 重点关注页源码隐藏销售 / 采购价格统计与价格列；设计曾写「与 SPU ROI 交互 UI 一致」。

- 关注清单前端一次添加上限为 **500**，盘点正文曾写「最多 100 个」——100 是 SPU ROI 页临时精确选择的上限。以 `Selection.tsx` 为准。
