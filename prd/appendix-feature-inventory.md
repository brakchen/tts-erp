## 0. 系统定位与产品边界

tts-erp 是面向 **TikTok Shop** 的本地分析型 ERP 数据服务。它把 TikTok Shop、妙手采购、Chrome 插件采集和汇率快照写入本地库，提供：

- 读侧分析 API 与运营工作台（浏览器页面）
- 后台定时同步（独立 worker）
- Chrome 插件接入（广告、订单域、拦截、监控）
- 内容资产与发布相关能力（素材库、数字人、换装视频、视频发布）

**明确不做的事（产品边界，不是缺陷）：**

- 不提供修改真实 TikTok 店铺订单、退货、取消或发货状态的写端点。系统允许写入本地分析库（同步数据、配置、人工成本等），但是「读侧分析系统」。
- 妙手没有对运营开放的 HTTP 业务界面；妙手数据由进程内同步任务拉取。
- 大部分业务读接口读本地库，不会在用户点开页面时临时打 TikTok。例外是 `GET /v2/tiktok-shop/products/{product_id}`（实时透传 Partner API，无运营页）。

**边界外但代码里确实存在的写行为（需单独认知）：**

- **广告监控插件（monitor）** 可在卖家已登录的 Seller Center 会话上，按规则自动关闭广告计划，并发送飞书通知。这不经过 ERP 的 TikTok 写 API。
- **视频发布** 通过外部设备和发布 worker，把视频发到 TikTok 内容侧（不是改店铺订单状态）。
- **换装视频（RunningHub）** 会向第三方云端发起计费生成任务。

## 1. 系统模块划分和每个模块的现有功能

按产品功能模块划分（不是代码目录）。入口路径均相对于部署根；生产公网常见前缀为 `/tts`，本机直连无前缀。运营页统一为 `/v2/pages/<页面id>`，侧边栏由服务端按权限下发。

### 1.1 登录与会话

- **目的**：运营人员用账号进入工作台，保持登录会话。
- **已实现**：用户名 + 密码登录；HttpOnly 会话 cookie；查看当前会话；退出登录；登录用户改自己的密码（**仅有 API，工作台顶栏无改密界面**，见第 5 节）。
- **入口**：`/v2/auth/login`（公开页，标题「登录」）。登录成功后跳转到 `next` 指定页，默认进入运营页。顶栏显示显示名，并提供「退出登录」。
- **文档差异**：根目录 `README.md` 仍写「浏览器可用 API key 换取 cookie」。代码与登录页已改为用户名/密码（`tts_erp_v2/api/v2/auth.py`、`frontend/src/pages/login/`）。

### 1.2 总览：控制台

- **目的**：登录后的经营全局入口，快速看到覆盖情况和同步健康度。
- **已实现**：
  - 按当前权限显示快速导航（采购工作台、SPU ROI、店铺注册、拦截配置、运行配置、广告日明细）。
  - 数据摘要：待录成本 SPU 数、已跟踪 SPU 总数、已注册店铺数；可跳转到对应页。
  - 已注册店铺精简表（名称、店铺 ID、地区、平台）。
  - 系统状态：API 健康检查、鉴权模式；同步任务表（严重级别、上次/下次运行、落后周期），约每 60 秒刷新。
- **入口**：菜单「总览 / 控制台」，`/v2/pages/dashboard`。

### 1.3 经营分析：SPU 盈利（SPU ROI）与重点关注 SPU

这两个菜单共用同一套盈利页面，口径由服务端按 **SPU 盈利 v10** 计算，前端只展示、不重算。金额统一为人民币（CNY）。

- **目的**：按店铺和经营日期看 SPU 及大盘的净收入、成本、广告、退款/全损/取消、净利润和 ROI；支持下钻证据。
- **已实现的功能点**：
  - 选择店铺；经营日起止（快捷：昨天 / 近 7 天 / 近 30 天 / 本月 / 不限）。未手选日期时，普通 ROI 页默认店铺当地「昨天」。
  - 预测样本天数：30 或 90（只影响大盘「预计最终」指标，不影响单 SPU 行预测；预测样本窗口与经营日期独立）。
  - 更多选项：临时覆写平台佣金费率；是否「含无活动 SPU」。
  - SPU 范围：按 SPU ID/标题搜索后应用；搜索、排序、分页只改明细展示，不改大盘。
  - **重点关注 SPU** 页：范围固定为该店关注清单；readwrite 可增删关注（最多 100 个），只读可浏览。
  - 经营概览卡片：当前 vs 预计最终（总单量、广告消耗、有效销售、退款/全损/国内取消、净利润、财务 ROI / 保本 ROI、广告系统 ROI / 保本 ROI 等）；销售价/采购价统计（均价、中位数、覆盖）；费率依据。
  - 数据更新时效条（各同步源 + 汇率快照）。
  - 商品经营明细表：可排序、分页（50/100/200），缺成本/高退款/亏损等标记，点击行下钻。
  - 下钻：利润构成、订单·物流、结算、售后、广告（服务端证据）；订单明细最多展示 500 条。
  - 「计算依据与数据说明」：计算时间、口径版本、汇率快照、成本基准、告警提示。
- **口径（产品语言，详见 `docs/business/spu-profitability.md` v10）**：
  - **当前指标**：所选经营窗口内、截至计算时点已确认的事实；未结算部分会用服务端标记的估算（如平台费）。
  - **预计最终**：在当前事实之上，用独立成熟样本（避开最近 7 个完整日后的 30/90 天已完结订单）估计尚未完结风险，只出现在大盘。
  - **成本优先级**：人工价 > 妙手货源价 > 40 CNY/件兜底。
  - 无可用汇率快照时整页不可算（服务端失败），不用固定汇率凑数。
  - 旧表 `reporting.product_profit_daily` 是粗略毛利快照，**不是**本页真相源。
- **入口**：
  - 菜单「经营分析 / SPU ROI」，`/v2/pages/spu-roi`
  - 菜单「经营分析 / 重点关注 SPU」，`/v2/pages/focused-spus`

### 1.4 经营分析：利润劣化告警

- **目的**：对同一 SPU，对比近期窗口与上一窗口的 ROI、净利润、订单数、广告消耗，及时发现变差。
- **已实现**：选店铺、截至日（店铺当地日）、比较窗口 3 或 7 天、活动范围（固定近 7 天活动，保留无单投放）或全部本店 SPU，或精确内部 SPU 编号；展示完整范围统计；对比表可展开单 SPU 明细，并跳转到对应经营日期的 SPU ROI 详情。
- **说明**：旧的「每日评估器写告警表」定时任务已于 2026-11-09 从调度注册表撤下。本页直接读现有盈利计算结果做 7/3 日对比，不读旧告警快照表。重新启用旧评估器属于产品决定，当前未挂调度。
- **入口**：菜单「经营分析 / 利润劣化告警」，`/v2/pages/spu-profit-deterioration`。

### 1.5 经营分析：广告日明细

- **目的**：浏览插件上报并落入本地的广告日事实，用服务端汇总评估投放。
- **已实现**：按店铺 Seller ID、广告账户、数据接口、日期范围、计划/商品 ID（部分匹配）筛选；刷新；分页。顶部汇总（记录行数、消耗 USD、归因订单、归因 GMV USD、加权 ROI）针对**全部匹配行**，不只是当前页。明细表可展开额外采集指标、复制 ID。源币种为 USD。
- **入口**：菜单「经营分析 / 广告日明细」，`/v2/pages/ad-daily`。

### 1.6 基础设置：采购工作台（人工成本）

- **目的**：按店铺核对货源价与人工采购成本，这是盈利计算里最高优先级的成本来源。
- **已实现**：
  - 店铺选择；视图：「全部 SPU」「缺成本候选」「最近提交」。
  - 筛选：搜索 SPU/标题、商品状态（在售/下架/停售等）、仅看有单、仅看未登记、仅看本页缺图；排序（成本/创建/更新，升序/降序）。
  - 表格展示当前人工成本、货源价（仅供参考）、图片（本地镜像，不是直接依赖 TikTok CDN）。
  - 单行编辑草稿（成本、币种、备注、生效时间），确认后提交；可保留草稿跨页/跨店。
  - 批量「提交本页已编辑行」（按行独立提交，不是整批原子事务，可中途停止后续行）。
  - 最近提交记录（变更前后、备注、生效/结束、提交时间）。
  - 只读账号可浏览，写入需 readwrite。
- **入口**：菜单「基础设置 / 采购工作台」，`/v2/pages/manual-costs`。

### 1.7 基础设置：店铺注册与授权

- **目的**：把店铺接入本地分析：插件发现或手工补录 → 配置 Partner App → 获取 TikTok 授权链接 → 卖家完成授权，之后定时同步才会按店扇出。
- **已实现**：
  - 列表筛选：名称/ID/编码搜索，发现来源（Ads 插件 / Monitor 插件），App 配置（已配置/未配置），OAuth 状态（未授权/已授权/需重新授权/待确认）。
  - 展示：区域与开店日期、插件资料同步时间、App 配置与 Service ID、授权状态。
  - 操作（readwrite）：手工补录、编辑信息（开店日期等；名称和区域在更新接口中不可改）、配置 App（Service ID，成对填写 App Key / Secret，密钥不会回读）、获取一次性授权链接。
  - 只读可看说明和列表，不能配置或生成链接。
  - 未授权店铺只在本页管理视角展示（注释说明：避免未授权店污染其它分析查询关联）。
- **辅助页**：`/v2/oauth/tiktok/onboard` 仅说明「请先到店铺注册台操作」，并给出 Partner Center 回调地址 `/v2/oauth/tiktok/callback`。回调完成后走结果页（成功/失败说明）。
- **入口**：菜单「基础设置 / 店铺注册」，`/v2/pages/shops`。

### 1.12 数据工具：请求拦截（配置 / 记录 / 统计）

- **目的**：为 Chrome 拦截插件维护采集规则，查阅已捕获请求，观察采集健康度。
- **拦截配置** `/v2/pages/intercept-configs`：
  - 按域名（服务端精确匹配）、启停状态筛选；列表、详情、新增、编辑、删除、启用/禁用；批量启停/删除；导入 JSON、导出**全部**配置（不受当前筛选/分页限制）。
  - 规则模式：白名单（记录匹配请求）/ 黑名单（完全跳过）；可设置是否记录头/体、描述、标签。
  - 页面有「搜索」框，但接口未实现搜索（见第 5 节）。
  - 列表、详情、导出和变更在策略上均需 **readwrite**（只读即使用户被授了该页，实际也读不了数据）。
- **拦截记录** `/v2/pages/intercept-requests`：
  - 筛选项：白名单、方法、域名、路径、状态码、时间起止；列表（时间、状态、耗时）；详情弹窗看请求/响应头和体。
- **拦截统计** `/v2/pages/intercept-stats`：
  - 卡片：总请求数、白名单命中、今日请求（UTC）、错误请求；按域名/方法/状态码分布；最近每日趋势图（UTC）。
- **菜单位置**：数据工具 / 拦截配置、拦截记录、拦截统计。

### 1.13 数据工具：视频发布

- **目的**：把视频素材排队，经外部设备和发布 worker 发到 TikTok，并核对结果。
- **已实现**：查看发布配置与设备心跳/状态；创建任务（受服务端 `canWrite` 条件约束）；任务列表按状态筛选（排队/执行中/失败/需核验/成功/已取消）；自动刷新（每 5 秒）；任务详情与脱敏诊断；按服务端返回的允许操作执行：取消、重试、再次自动核验、重试清理、重新上传、确认已发布、编辑发布设置等。
- **预置角色**：内置「运营」默认**不含**本页；需单独授权 `page:video-publish`。会话用户还受该页权限点约束；API key 访问默认更严（除非环境开关允许 readwrite key）。
- **入口**：菜单「数据工具 / 视频发布」，`/v2/pages/video-publish`。

### 1.14 内容资产：资产管理、数字人、换装视频

**资产管理** `/v2/pages/media-assets`：

- 页签：素材包 / 视频 / 全部素材。
- 搜索（名称、说明或标签）；全部素材可按类型（图片/视频）筛选。
- 上传素材；查看、编辑资料/标签、删除（若被素材包或数字人引用则先解除）。
- 视频可多选「加入已有包」或「新建素材包」；包可命名、增删视频、查看详情。

**数字人** `/v2/pages/digital-humans`：

- 档案列表，状态筛选（启用中 / 已归档 / 全部）；新建档案；上传/更换形象照片；编辑资料。
- 打开档案后挂载素材包（以及一套较旧的「素材关联」入口）。
- 归档（可恢复）、删除档案（全局素材文件保留）。

**换装视频** `/v2/pages/runninghub`：

- 选择服装图、人物模板（来自数字人已挂载的参考视频）、款式编号/SKU，预览生成计划（可「仅跑首段」）。
- 保存批次、启动（明确确认将产生 RunningHub 费用）、查看批次/成片、下载单段或整批 ZIP、终止、首段后再继续剩余段、失败任务恢复/重试。
- 工作流配置、凭据引用、账户信息：普通只读可见部分状态；**检查/保存工作流、账户与部分恢复类操作需 admin**。

### 1.15 数据同步与插件接入（无独立「插件管理」菜单，但是核心能力）

运营在工作台里看到的是结果（店铺、广告、盈利、拦截记录、同步状态）；数据采集侧由插件 + 同步 worker 完成。

| 插件（`plugins/`） | 用户能做什么 | 与 ERP 的关系 |
| --- | --- | --- |
| **ads-data-sync** 广告数据同步 | 在已登录的 Seller Center 上配置 ERP 地址和令牌，发现广告计划，同步每日商品分析与变更日志 | 上传到 `/v2/analytics/sync/*`；可向 ERP 登记/查询店铺元数据。会话分析代码还在，但已从启用集合中移除 |
| **order-data-sync** 订单数据同步 | 绑定 Seller Center 页面，同步订单、详情/历史、物流、结算、售后 | 上传到 `/v2/order-sync/*`（域：orders / order_details / order_history / logistics / statements / after_sales） |
| **tts-request-intercept** 请求拦截 | 按服务端规则捕获 TTS 请求并分批上传；Popup 看待同步量和日志导出 | `/v2/intercept/*`；规则在「拦截配置」页维护 |
| **monitor** 广告监控 | 扫描在投 GMV Max 计划，按规则自动关闭，飞书通知；策略可从 ERP 运行配置拉取 | 会向 ERP 登记店铺并可用运行配置；关计划走卖家浏览器会话，不走 ERP 写 API |
| **miaoshou-order-capture** 妙手拦截 | 在妙手包裹页本地捕获两个接口响应，可导出 JSON | **不上传 ERP**，记录只存在本机扩展里 |

插件发现的店铺可通过 `/v2/plugin/shops/*` 登记到本地店铺主档（不必先 OAuth）。OAuth 授权后，才进入 TikTok 官方同步任务的「已授权店铺」扇出。

另有只读/工具 API，**无对应运营菜单**：汇率查询与换算 `/v2/fx/*`，商品/订单只读列表 `/v2/commerce/*`，成本快照与旧利润日报 `/v2/reporting/cost-snapshots|profit-daily`，给 LLM 用的系统自描述 `/v2/llm-context`，商品实时透传 `/v2/tiktok-shop/products/{id}`。

### 1.16 基础设施（对产品可见的部分）

- 生产由 API 服务、同步 worker、巡检 timer 三个进程组成；改同步逻辑后需单独重启 worker。
- 对象存储用于 SPU 主图镜像、媒体资产、发布视频等。
- 访问失败有拒绝限流；文档接口在配置了独立账号后另受 Basic Auth 保护。

## 2. 主要用户角色与权限

### 2.1 两种登录方式

优先级固定为：**有效会话 cookie > Authorization: Bearer API key > X-API-Key**。

| 方式 | 谁在用 | 怎么用 | 权限模型 |
| --- | --- | --- | --- |
| 浏览器会话 | 运营在工作台 | `/v2/auth/login` 用户名+密码，服务端发 HttpOnly cookie；写操作还需浏览器约定头（防跨站） | **API 档位**（readonly / readwrite / admin）+ **页面权限点**（`page:<页面id>`） |
| API key | 插件、脚本、外部集成 | Bearer 或 X-API-Key | 只有 API 档位，**没有页面权限**；不走页面 ACL |

公开（无需登录）路径包括：健康检查、路由索引、OpenAPI/文档、登录/退出/当前会话、TikTok OAuth 回调、静态资源。其余默认要鉴权。未在策略中单独列出的路径，默认要求 **admin**。

### 2.2 API 档位（路由角色）

顺序：`readonly` < `readwrite` < `admin`（高等级包含低等级）。

产品层常见划分：

- **readonly**：看经营分析、店铺列表、广告明细、拦截记录/统计、媒体只读、盈利与劣化、枚举只读等。
- **readwrite**：在只读之上，可维护人工成本、店铺注册/App/授权链接、关注 SPU、拦截配置（含读取）、插件上报、手动触发同步、运行配置、媒体/数字人/换装生成、视频发布写操作等。
- **admin**：用户与角色管理、枚举映射的增删改、启停同步周期调度、限流热加载、RunningHub 工作流/账户类配置、部分高风险清理操作等。

关键细化（以代码为准）：

- `/v2/pages/sync-jobs`、`/v2/pages/runtime-configs`：打开页面就要求 readwrite。
- 拦截配置相关 API（`/v2/intercept/configs*`）整段要求 readwrite（包括 GET、导出）。
- 枚举映射：GET 为只读；PUT/DELETE 在 handler 内再要求 **admin**（前端文案也是 admin）。`accounts/pages.py` 里的「写操作最低档位」把 enum-map 写成了 readwrite，**与实现和页面提示不一致，以 handler / 页面为准**。
- 同步：手动触发 = readwrite；启停周期 = admin。
- 改自己的密码：任何已登录会话用户可调；API key 无会话，不能用该接口。
- 视频发布：会话用户还需 `page:video-publish`；API key 默认按更严格的 admin 门槛（可用环境开关放宽，产品上应视为默认收紧）。

前端的 `roleCapabilities`（能否看到写按钮）只是展示提示，真正放行以服务端为准。

### 2.3 预置业务角色（给用户账号用）

来源：`tts_erp_v2/accounts/pages.py` 的 `BUILTIN_ROLES`。管理员可另建自定义角色（自选页面 + API 档位）。

| 预置角色 | 显示名 | API 档位 | 默认可访问页面 |
| --- | --- | --- | --- |
| admin | 系统管理员 | admin | 全部页面 |
| operator | 运营 | readwrite | 除「用户管理」「视频发布」外的全部页面 |
| viewer | 只读分析 | readonly | 仅：控制台、重点关注 SPU、SPU ROI、广告日明细、拦截统计 |

因此：**只读分析默认看不到**利润劣化、采购工作台、店铺注册、枚举、运行配置、定时任务、拦截配置/记录、以及全部内容资产页。若业务需要，只能改角色授权，不是系统自动放开。

### 2.4 页面权限点与写操作提示档位

侧边栏、角色编辑勾选、权限种子同源，共 18 个页面权限：

`page:dashboard`、`focused-spus`、`spu-roi`、`spu-profit-deterioration`、`ad-daily`、`manual-costs`、`shops`、`enum-map`、`runtime-configs`、`sync-jobs`、`users`、`intercept-configs`、`intercept-requests`、`intercept-stats`、`video-publish`、`media-assets`、`digital-humans`、`runninghub`。

设计上的写操作最低档位（`PAGE_MIN_WRITE_TIER`，提示用）：采购/店铺/运行配置/定时任务/拦截配置与记录/视频发布/三类内容资产 → readwrite；用户管理 → admin。枚举映射该表写的是 readwrite，但实际写入是 admin。

会话用户访问 `/v2/pages/<id>` 必须持有对应 `page:<id>`；`/v2/users*`、`/v2/roles*` 绑定 `page:users`；`/v2/video-publish*` 绑定 `page:video-publish`；`/v2/runninghub/*` 绑定 `page:runninghub`。其它数据 API 主要靠 API 档位。

### 2.5 生产默认策略

- 生产使用 `TTS_ERP_AUTH_MODE=enforce`（拒绝无凭证或权限不足的请求；浏览器 HTML GET 未登录会跳到登录页）。
- 代码里环境变量**未设置**时默认是 `off`（全部放行）。配置了无法识别的值会**失败关闭为 enforce**。
- 另有 `shadow` 模式：实际仍放行，但记录本应拒绝的结果，用于灰度，不是生产默认。

## 3. 核心业务实体和关键用户流程

### 3.1 核心实体及关系

```text
店铺（渠道账户 ChannelAccount）
  ├── TikTok App 配置 / 授权凭证（授权后才能跑官方同步）
  ├── 插件发现来源与上报时间（Ads / Monitor 等）
  ├── 商品 SPU（ChannelProduct）── SKU 变体
  ├── 销售订单 ── 订单行（归属某个 SPU/SKU）
  ├── 履约运单 / 轨迹
  ├── 售后 case / 行（退货退款、取消等）
  ├── 结算：对账单、交易、费用组件、打款
  ├── 重点关注 SPU 清单
  ├── 店铺平台费率估算（供未结算净额估算）
  └── 广告日明细（插件，按计划/商品/日）

采购与成本：人工成本（按 SPU，可有生效区间）
             妙手货源价 / 采购价候选 → 回填到采购主档
             成本快照、SPU 主图本地镜像

汇率快照：盈利与换算的必备依据（缺失则盈利不可算）

同步任务运行记录 / 游标 / 问题

拦截：规则配置、浏览器会话、拦截请求记录

内容：媒体资产（图/视频）── 素材包 ── 数字人档案
      换装视频批次 / 成片
      视频发布任务 / 尝试 / 设备心跳

账号：用户、角色（档位+页面）、会话；以及独立的 API key
运行配置：配置项、版本、加密凭证引用
枚举映射：类型 + 英文值 → 中文标签
```

插件落库的 Chrome 订单/物流/结算/售后表，与官方同步进入的 commerce / fulfillment / after_sales / finance 是两套来源，共同服务分析，不在工作台里作为两套「订单中心」呈现。

### 3.2 关键用户流程（仅代码里存在的）

**A. 新店从发现/补录到授权上线**

1. 广告或监控插件在 Seller Center 绑定店铺后，向 ERP 登记店铺元数据（也可在店铺注册台「手工补录」shop_id 等）。
2. 运营在「店铺注册」核对名称、区域、开店日期、插件是否在上报。
3. readwrite 为该店配置 Partner App（Service ID + Key/Secret 成对填写）。
4. 点击「获取授权链接」，用目标店铺卖家账号打开链接完成授权（链接有有效期、一次性）。
5. TikTok 回调 `/v2/oauth/tiktok/callback`，系统交换令牌并更新授权状态。
6. 之后 `token.refresh` 与各 `tiktok.*` 任务按「已授权店」自动同步；控制台和定时任务页可看到运行结果。  
   说明：插件数据上报不依赖「已授权」；官方订单/商品/物流/财务同步依赖授权。

**B. 日常看经营与 SPU 盈利**

1. 打开控制台，看待录成本、店铺数、同步是否落后。
2. 进入 SPU ROI（或重点关注 SPU），选店和经营日期（默认昨天），看大盘当前/预计指标和明细。
3. 需要跟进特定商品时：搜索并限定 SPU，或在重点关注页维护清单。
4. 点击一行查看订单/物流/结算/售后/广告证据。
5. 若怀疑近期变差，到「利润劣化告警」做 3/7 日对比，再跳回 ROI 详情。
6. 需要看广告原始日数据时，打开「广告日明细」按账户和日期筛选。  
   前置：汇率任务要有可用快照；成本尽量在采购工作台补全，否则走货源价或 40 CNY 兜底（页面会给依据/提示）。

**C. 人工维护采购成本**

1. 打开采购工作台，选店，常用「缺成本候选」。
2. 核对货源价与主图，编辑人工成本草稿，确认提交（或本页批量提交）。
3. 在「最近提交」核对历史。下次盈利计算使用新的人工价（计算当日成本口径，不回溯改历史窗口算法）。

**D. 插件上报广告 / 订单 / 拦截**

1. 安装对应 Chrome 扩展，填写 ERP 地址与 **readwrite** API key（拦截插件另有自己的配置约束，见第 5 节）。
2. 在已登录的 Seller Center（或规则指定站点）保持可用页面；插件按调度采集并上传。
3. 广告进入广告日明细和盈利中的广告消耗/归因；订单域进入分析库并出现在盈利证据中。
4. 拦截：先在「拦截配置」维护白/黑名单，再在「拦截记录/统计」验证采集是否正常。
5. 监控插件按本地或 ERP 运行配置的策略扫描，必要时自动关计划并通知飞书（不经过 ERP 订单写接口）。

**E. 查看与干预同步**

1. 控制台或定时任务页查看各 job 的上次运行、落后周期、严重级别。
2. readwrite 可「立即执行」某一任务（TikTok 类可针对单店或全部已授权店；全店铺会二次确认）。
3. admin 可停用某个任务的周期调度（手动触发仍可用）。
4. SPU ROI 页还有「数据更新」条，按店展示各源新鲜度。

**F. 内容生产到发布（可选链路）**

1. 在资产管理上传图/视频，组成素材包。
2. 创建数字人档案，挂上形象照和素材包。
3. 在换装视频中选服装图 + 人物模板，确认费用后出片并下载。
4. 在视频发布中创建任务、等待设备执行、按允许操作核验/重试/确认已发布。  
   各步都受页面权限和读写档位约束；换装的关键云端配置还要 admin。

**G. 权限治理**

1. 管理员在用户管理中建账号、分配预置或自定义角色、必要时重置密码或吊销会话。
2. 用户自行登录；改自己的密码目前只能走 API，工作台没有入口。

## 4. 前后端结构、入口页面和菜单/路由

### 4.1 技术形态（产品需要知道的程度）

- **不是**浏览器里自己切路由的单页应用。
- 运营界面是 **服务端页面 + React 水合**：每个 `/v2/pages/...` 由后端输出 HTML 壳和导航数据，再加载对应前端模块。点侧边栏是整页跳转。菜单文案、分组、可见性全部由服务端 `PAGES` 注册表按权限生成。
- 旧的服务端模板整页渲染已经退役。`pages.py` 里仍留着一套侧边栏 HTML 片段，但**没有路由再走这条渲染路径**，只是代码里的遗留参考，用户看不到两套菜单皮肤。
- 登录页、授权说明页、OAuth/错误结果页是同一套前端的「辅助页」，无侧边栏。
- 同时提供 `/v2/*` JSON API，供页面和插件使用。没有第二套仍在服务的运营站点。

### 4.2 对用户可见的入口一览

工作台品牌：侧栏「tts / erp」，顶栏上下文「运营工作台 / <分组>」，标题为当前菜单名。可折叠侧栏。

### 4.3 各页主要区块、筛选和操作（画原型用）

**登录**：左/品牌区 + 表单（用户名、密码、显示密码、登录）。失败可查询当前会话做核对，不自动当成登录成功。

**控制台**：页引「经营全局，一目了然」；快速导航按钮组；数据摘要三张卡（待录成本 / SPU 总数 / 已注册店铺）；已注册店铺表；系统状态（API 与同步任务表）。

**SPU ROI / 重点关注 SPU**：经营概览（当前 vs 预计最终、价格统计、费率依据）；工具条（当前店铺、起始日/截止日、日期快捷、预测样本、更多：临时佣金费率、含无活动 SPU）；SPU 搜索与已选/已关注标签（关注页可保存清单）；数据更新条；商品经营明细表 + 分页 + 每页条数；行下钻证据；计算依据折叠区；无店铺时强制先选店弹窗。

**利润劣化告警**：对比范围（店铺、精确 SPU 内部编号、比较窗口 3/7 天、截至日、活动范围/全部本店、每页条数）；应用/重置/刷新；完整范围统计；对比表（ROI、净利润、订单数、广告消耗，本期/上期及展示变化）；展开明细并可链到 SPU ROI。

**广告日明细**：筛选（店铺 Seller ID、广告账户、数据接口、开始/结束日期、计划或商品 ID、每页行数）；应用/重置/刷新；全部筛选结果汇总；明细表与行详情。

**采购工作台**：店铺与视图（全部 / 缺成本 / 最近提交）；搜索与状态/排序/仅看有单等；成本表（内部 PK、标题状态、人工成本/货源价、时间、图片、编辑）；编辑弹窗（成本、币种、备注、生效时间）；本页批量提交；最近提交记录。

**店铺注册**：页引「店铺接入管理」+「刷新店铺」「手工补录」；筛选（搜索、发现来源、App 配置、OAuth 授权）；店铺表（店铺、区域/开店日期、插件资料同步、App 配置、OAuth 授权、操作：编辑信息 / 配置 App / 获取授权链接）；分页；相应弹窗。只读提示需写入权限。

**枚举映射**：分类筛选；新增/刷新；映射表（英文值、中文标签、排序、编辑/删除）。维护按钮对非 admin 会提示权限不足。

**运行配置**：配置列表（可显示已停用）；新建；配置工作区（概览、改草稿、检查发布、发布历史、停用/恢复）；凭证管理（不回读明文）。

**定时任务**：刷新；任务表（任务、周期、范围、状态、上次运行、周期调度启停、立即执行）。立即执行可选店铺；全店铺二次确认。文案写明：触发要 readwrite/admin，启停要 admin。

**用户管理**：页签「用户 / 角色权限」。用户：搜索、状态、刷新、新建、行内编辑显示名/分配角色/重置密码/会话管理/启停。角色：刷新、新建、编辑、删除（受内置角色限制）、页面勾选与 API 档位。

**拦截配置**：筛选（域名、状态、搜索框——搜索不生效，见第 5 节）；新增、导入、导出全部；批量启用/禁用/删除；表格（域名、模式、状态、记录头/体、描述、标签、详情与编辑、启停）。

**拦截记录**：筛选（白名单、方法、域名、路径、状态码、起止时间）；表格与详情（请求/响应头和体）。

**拦截统计**：四张汇总卡；分布表（域名/方法/状态码）；「每日请求（UTC）」趋势图。

**视频发布**：发布配置与设备状态；创建任务区（受服务端能力字段约束）；自动刷新开关；任务表（状态筛选）；行内按允许操作出按钮；详情/诊断。

**资产管理**：类型页签（素材包 / 视频 / 全部素材）；搜索与类型；上传；素材卡片（查看/编辑/删除）；视频多选后加入包或新建包；包详情编辑。

**数字人**：状态筛选、新建、档案卡片（形象照、查看/编辑、归档或恢复、删除）；档案内素材包工作区。

**换装视频**：选图与人物模板、款式/SKU、仅跑首段、生成计划确认（含费用确认）、批次记录、启动/终止/续跑、成片预览与下载；admin 可见工作流 JSON、凭据/账户检查等。

**新店接入授权说明**：说明文字 +「前往店铺注册台」+ 回调地址。

### 4.4 API 有、运营菜单没有的能力

以下接口存在，但没有对应菜单页（分析页会间接用到一部分）：

- 商品/SKU/订单/订单行/店铺订单汇总的只读列表
- 汇率最新快照与换算
- 成本快照、旧版利润日报、缺成本商品列表（采购页走的是人工成本与 coverage，不是单独「快照页」）
- 实时透传 TikTok 商品详情
- LLM 系统自描述
- 管理端限流查看/重置、插件数据清理（高风险，admin）

画「订单中心 / 售后中心 / 结算中心 / 汇率台」原型时，不能当成现有页面，它们目前只在 API 和盈利下钻里出现。

## 5. 明显缺口或实现不完整的功能

每条都有代码或文档证据。读侧系统故意不做的 TikTok 订单写操作不列为缺陷（见第 0 节）。以下只客观描述现状，不含改造建议。

1. **工作台没有「修改自己密码」的界面**  
   证据：`POST /v2/auth/change-password` 已实现（`tts_erp_v2/api/v2/auth.py`），权限策略也单列该路径；但 `frontend/src/` 中无改密表单，顶栏 `SessionActions.tsx` 只有显示名和「退出登录」。  
   影响：登录用户无法在页面里改密；管理员可以在用户管理里给别人重置密码。

2. **拦截配置页的「搜索」不会真正过滤**  
   证据：页面把 `search` 作为查询参数提交，并写明「当前接口未实现搜索，不保证搜索条件生效」（`frontend/src/pages/intercept-configs/index.tsx`）；列表 API 只接受 `domain`、`enabled`、分页（`tts_erp_v2/api/v2/intercept.py` 的 `list_configs`）。  
   影响：用户以为能搜 endpoint/描述/标签，结果列表不变（域名精确筛选仍然有效）。

3. **登录方式文档落后于代码**  
   证据：`README.md`「鉴权与访问路径」写浏览器用 API key 换 cookie；实现和登录页已是用户名+密码。  
   影响：按 README 操作的人会以为工作台仍用 API key 登录。生产鉴权模式本身仍是 enforce（与 README 一致）；未配环境变量时代码默认 `off`，这是部署约定，不是页面缺口。

4. **「只读分析」预置角色覆盖面窄，且与部分分析页不齐**  
   证据：`BUILTIN_ROLES["viewer"]` 只有控制台、重点关注、SPU ROI、广告日明细、拦截统计，不含利润劣化、采购、店铺、拦截配置/记录等（`accounts/pages.py`）。  
   影响：发一个「只读分析」账号后，对方默认进不了劣化告警和成本/店铺页，除非改角色。

5. **枚举映射「谁能改」的登记表与真实限制不一致**  
   证据：`PAGE_MIN_WRITE_TIER` 将 enum-map 标为 readwrite；页面写「维护需要 admin」；`PUT/DELETE /v2/config/enum-map` 调用 `require_role_at_least(..., "admin")`。  
   影响：若只按登记表给运营 readwrite + 该页权限，对方能打开页面但保存会被拒绝。

6. **广告插件的「会话分析」未作为生产同步集合启用**  
   证据：`plugins/ads-data-sync/README.md` 写明会话分析实现仍在，但已从集合注册表和默认设置移除；当前启用的是商品分析和变更日志。另有文档中的 Outbox/重试重构「尚未实现」。  
   影响：ERP 广告日明细和盈利里的广告事实，不包含该未启用集合的数据。

7. **广告「今日表固化到日表」的定时任务已停用**  
   证据：`scheduler.py` 注释：`plugin.ad_merge_today2daily` 于 2026-09-19 停用；`plugin.ad_today` 表保留为可能的回填目标。广告浏览页读的是 `plugin.ad_daily`。  
   影响：不存在把「今天实时表」自动滚到日表的调度；日数据依赖插件现行的 T-1 日同步路径。

8. **利润劣化「每日评估写告警表」已不再调度**  
   证据：同一 `JOBS` 注册表明确不再注册 `analytics.spu_profit_deterioration_alert`；对比页改读盈利结果。旧评估模块和快照表仍留在代码库中，但无读取方。  
   影响：用户不会收到基于旧评估器的自动告警写入；只能在对比页主动查询。页面功能本身是完整的对比，不是空白占位。

9. **订单 / 履约 / 售后 / 结算没有独立运营列表页**  
   证据：存在 `/v2/commerce/sales-orders*` 等只读 API，以及售后/结算数据模型与同步任务；`frontend/src/pages/` 无订单中心、售后中心、结算中心。这些事实出现在 SPU 盈利下钻里。  
   影响：不能按订单号在独立页面里浏览全量订单或处理售后（系统也本就不提供向 TikTok 回写状态）。

10. **汇率、旧版利润日报、成本快照、商品实时透传没有运营页**  
    证据：`/v2/fx/*`、`/v2/reporting/profit-daily`、`/v2/reporting/cost-snapshots`、`/v2/tiktok-shop/products/{id}` 有 API；无对应 `PAGES` 项。`reporting.profit_daily` 在代码中标记为已过时的粗略毛利，但仍在调度。  
    影响：运营不能在菜单里直接查汇率或旧日报；盈利页会消费汇率快照。旧日报若仍在跑，也不等同于 SPU 盈利。

11. **拦截插件的服务端地址在扩展内写死**  
    证据：`plugins/tts-request-intercept/README.md` 写明服务器地址固定，使用者只手动填 API Key。  
    影响：不能像广告/订单插件那样在 Popup 里改 ERP 地址；换环境需要改插件构建或另行发版。

12. **妙手订单捕获插件不接入 ERP**  
    证据：`plugins/miaoshou-order-capture/README.md`：只本地存最近记录，导出 JSON，不向外部服务器上传。ERP 侧妙手数据来自官方同步任务，不是这个插件。  
    影响：不要把它当成已接通的「妙手数据自动入库插件」。

13. **授权「控制台」页不能在本页完成授权**  
    证据：`render_oauth_onboard_page` 和 `frontend/src/pages/oauth-onboard/` 只做说明并跳转店铺注册台；生成链接必须带店铺身份，已收到店铺页。  
    影响：书签若还指向 `/v2/oauth/tiktok/onboard`，用户会发现只是跳板，不是可操作的授权向导。

14. **部分管理模块文档仍写「整个 /v2/admin 都是 admin」**  
    证据：`app.py` / `admin.py` 模块注释如此；实际店铺注册/更新和手动触发同步只要 readwrite，启停周期和限流等才是 admin（handler 与 access 策略一致）。  
    影响：权限方案若只看旧注释会把运营可做的店授权和手动同步误判为必须管理员。

以上之外，未发现「菜单有入口但页面是即将上线的空壳」或「路由指向 stub 组件」的情况：18 个菜单页都有完整前端模块。`docs/plans/` 下有不少尚未落地的方案（例如统一工作区、插件架构清理），按要求不计入现有功能，也不展开为改造清单。
