# 原型按现网逐页复刻（补需求）

> 状态：开发已按第 9 节返工提交，待测试回归、产品复验。  
> 日期：2026-11-12  
> 提出人：chen  
> 范围：只改 `prd/prototypes/`，不改线上业务代码，也不提前落地尚未拍板的产品取舍。  
> 本需求取代 `02-prototype-alignment.md` 第 9 节的验收结论。02 已完成且仍然有效的部分（`tokens.css`、导航壳层、三种预置角色与上限、不提前落地未拍板取舍）不必推倒重来；未通过的是各页正文必须按现网功能和布局复刻，不能停留在中保真示意。

## 1. 背景

`02-prototype-alignment.md` 按「配色 + 壳层 + 角色/上限」验收通过。但打开原型对照现网时，页面正文对不上。chen 明确要求：原型要复刻现在**所有页面**的功能与布局，不是只改 SPU ROI 一页，也不是只改配色。

根因：上一轮主要改了令牌和壳层，18 个菜单页和登录等辅助页的正文仍是中保真摘要——分区被改写、指标被压扁、对话框和核对步骤被省略。最典型的是 SPU ROI「经营概览」：现网是「销售 / 成本 / 利润」三张卡片，原型却收成「一张 ROI 表 + 一排指标卡」，价格统计还被挪到概览外面。视频发布、素材、数字人、换装生成、运行配置等页也存在同类简化。

## 2. 目标

打开 `prd/prototypes/` 任意一页，其分区结构、指标与字段、表格列、筛选和操作入口、对话框/抽屉、空态/加载/失败重试、只读表现，都应能对上现网对应页面。允许使用标注过的示例数据、不连接后端，但不允许把现网已有的信息结构简化成示意卡片。

真相源：

1. v2 前端页面模块 `frontend/src/pages/*` 及共享壳层、`tts_erp_v2/static/css/tokens.css`、`tts_erp_v2/accounts/pages.py`
2. 已校准的 `prd/00-prd.md`、`prd/01-information-architecture.md`、各页文档
3. 过时或已归档文档一律不作为依据

若文档与代码冲突，以代码为准。

## 3. 目标用户与使用场景

产品评审时，评审者把原型和现网同一页放在一起对照，功能和布局能一一对上，而不是对着一张「大概差不多」的示意图猜现网能力。

## 4. 用户故事

- 作为评审者，我打开任意一页原型，应能看到与现网相同的分区、指标、字段、表格列和操作入口，以免按被简化过的界面做后续判断。
- 作为评审者，我在原型里走一遍现网已有的对话框、抽屉、上传/预览和提交核对步骤（可用示例状态演示），不应发现这些入口被省略。

## 5. 功能范围

### 5.1 要做

覆盖全部工作台页面，共 21 页：

- 菜单页（18）：仪表盘、重点关注 SPU、SPU ROI、利润劣化、广告日明细、采购工作台、店铺注册、枚举映射、运行配置、同步任务、用户管理、拦截配置、拦截请求、拦截统计、视频发布、素材、数字人、换装视频生成
- 辅助页（3）：登录、新店接入授权说明、授权结果

复刻粒度（每一页都要达到，不以「看起来像」为达标）：

- 分区与卡片结构：几列、谁套在谁里面，与现网一致
- 现网可见的全部指标、表单字段、表格列、页签、可展开说明
- 现网已有的操作：按钮、对话框、抽屉、上传与预览、提交后的核对/确认步骤（不接后端，用示例状态演示即可）
- 空态、加载中、失败可重试、只读禁用，按该页现网表现保留
- 指标旁的「？」口径说明、可展开的计算/预测依据，按现网保留

不要求把每一种 HTTP 错误文案的全部变体都做成独立页面；但关键流程的可见步骤不能省。

02 已对齐的壳层、令牌和三种预置角色保持不变，并继续遵守原先的逻辑约束（无独立订单/售后/结算页、无改密入口、无 API key 管理页、授权说明页只是跳板、拦截配置搜索框保持现网「不会真正过滤」、插件不单独出原型页）。

### 5.2 不做

- 不修改线上业务代码、不改现网样式实现。
- 不把 chen 尚未拍板的产品取舍做进原型或现网，包括：预置运营是否包含视频发布、只读是否进入利润劣化页、利润劣化页是否改名、是否补改密入口、拦截配置无效搜索框是补齐还是去掉。
- 不新做插件 Popup/扩展设置原型，不新做 API key 管理页面。
- 不把已对齐的 tokens / 侧栏壳层推倒重来。

### 5.3 逐页差距（实施时对照现网模块补齐）

下列差距根据 2026-11-12 对照 `frontend/src/pages/*` 与 `prd/prototypes/*.html` 整理，作为本轮必须补上的范围。若实施时现网又有更新，以当时源码为准，并在对应页面文档中记录差异。

#### 登录 `login`（`frontend/src/pages/login`）

补左侧品牌区的装饰图，eyebrow 为「YOUR BUSINESS, IN FOCUS」，密码「显示 / 隐藏」切换，提交中「登录中…」，以及登录结果未确认时「查询当前会话」的核对流程（查询中、查询完成、允许手动重新登录且不会自动提交）。表单与品牌文案按现网，不要沿用被简化的示意版。

#### 新店接入授权 `oauth-onboard`

与现网基本对齐，本轮以核对为准；若文案或权限列表有出入再补，不作为重点返工。

#### 授权结果 `message`

补「授权链接」及「链接有效至 …，仅可使用一次」。

#### 仪表盘 `dashboard`

- 「系统状态」与「数据同步状态」在现网是两张独立卡片，原型把同步表嵌进了系统状态，需拆开。
- 系统状态按现网展示：API 正常/异常与 auth 模式，以及「数据库 · PostgreSQL」「存储 · MinIO」「同步服务 · APScheduler」（接口未提供时也要写出「健康状态未知（接口未提供）」）。
- 同步表列应为：健康、作业、周期、最近一次同步、预计下次同步、状态（含落后周期、最近错误、从未运行）；不要改成另一套「任务 / 严重级别」列。
- 数据摘要、店铺列表、系统状态、同步状态各自保留加载中 / 失败可重试。
- 保留现网已有的跳转：待录成本、SPU ROI、管理店铺、枚举映射管理；快速导航按当前权限显示那六个常用入口。
- 保留无店铺、未命名店铺的展示。

#### 重点关注 SPU `focused-spus`、SPU ROI `spu-roi`（共用 `frontend/src/pages/spu-profitability`）

这是上一轮验收失准的典型例子，必须按现网模块复刻，不得再使用被压扁的概览。

「经营概览」必须是「销售 / 成本 / 利润」三张卡片，不能收成「一张 ROI 对照表 + 一排指标卡」，也不能把价格统计拆到概览外面当作兄弟区块。

- 销售卡：GMV、有效 GMV、总单量、有效单量、退款数、退款率、国内取消量、国内取消率；在 SPU ROI 页把销售价格统计嵌在本卡内。
- 成本卡：采购成本、广告成本、全损成本、全损量、全损率、费率依据、采购价格统计、预计新增全损；可展开「预测依据」（样本窗口、已完结样本单、已完结全损单、已完结订单全损率）。
- 利润卡：预测状态与口径帮助；「当前」与「预计最终」对照（盈亏状态、净利润 / 净收入，以及预计净利润 / 预计净收入）；ROI 对照表；未结算、已送达未结算、待完结风险。
- 各指标旁的「？」口径说明按现网保留。
- 重点关注页按现网隐藏价格统计，明细表无「实际ROI」列；关注清单一次上限 500。SPU ROI 页精确多选上限仍为 100。

同一模块的其余部分按 `index.tsx` 复刻：筛选与范围工具条、精确选择、新鲜度、商品经营明细、下钻抽屉的页签与字段（订单号、已结算、已到海外、全损、对账单时间、退款、计划与消耗等）、「计算依据与数据说明」、未选店铺时的「请选择店铺」、商品图片预览。可用示例数据，但结构和入口不能少。

#### 利润劣化 `spu-profit-deterioration`

补「必要来源」「广告观测范围」「限制说明」；对比结果的上升 / 持平 / 下降、展示差额与变化率、不可比较原因；单 SPU 对比明细；计算时间说明（不是数据更新日期）；日期越界、SPU 输入限制（最多 100 个内部编号等）校验提示。页面名称保持现状，不提前改名。

#### 广告日明细 `ad-daily`

相对接近。补行级「更多 / 收起」、加载 / 空态 / 失败可重试、页头口径说明（金额保持 TikTok 广告源币种 USD，不套用盈利看板汇率）、分页「N 条 / 页」。记录详情与「全部筛选结果汇总」结构与现网保持一致。

#### 采购工作台 `manual-costs`

补提交后的「提交结果核对」（GET 核对不能自动当成提交成功，也不会自动重试）、逐行非原子提交与「已请求停止后续行」的说明、主图放大、历史表字段、店铺加载中 / 暂无可选店铺、只读被拒绝时草稿保留、人工价与货源价并排展示。保留「切换店铺、视图、分页或关闭编辑不会丢失草稿」。

#### 店铺注册 `shops`

补授权链接复制、有效期与一次性说明、提交结果核对、放弃未保存修改的确认、Service ID 未填、自动同步已接入、密钥需成对填写的校验、只读时「配置和授权需要写入权限」的说明。

#### 枚举映射 `enum-map`

补提交 / 删除后的结果核对（核对后由用户明确再提交或再删除，不自动重放原命令）、读取冷却、加载失败可重试、删除确认文案。

#### 运行配置 `runtime-configs`

与现网差距较大。按现网补：发布历史（查看某版内容、使用某版内容、带退役灰度数据的版本不可作为恢复来源）；检查并发布时的「本次内容变更 / 当前生效内容 / 准备发布的内容 / 最新服务端内容」对照；凭证管理的新增 / 更新 / 归档 / 恢复、明文不回读、未保存输入拦截、校验规则预览与自定义 Schema、草稿 / 已发布 / 已停用等状态。不要只保留一个 JSON 草稿框和一张简表。

#### 同步任务 `sync-jobs`

补与现网一致的任务清单字段（开始 / 结束 / 下次预计、间隔秒数、从未运行、存在运行错误但详情暂不公开、启停与立即执行的权限差异）；命令提交后的查询核对，冷却期内不自动重试。保留确认全店铺执行对话框。

#### 用户管理 `users`

补「角色权限目录」页签与现网字段；重置密码的「新密码」输入；会话状态（活跃 / 已过期 / 已吊销）及吊销时间；提交结果核对与冷却说明；自定义角色相关能力按现网保留。非 admin 进入时给出只读提示。

#### 拦截配置 `intercept-configs`

补配置表单中现网已有的「记录请求/响应头」「记录请求/响应体」等字段；导入结果（成功 / 跳过 / 错误条数）；批量启停 / 删除的确认与影响条数；提交结果核对；当前公开配置详情（创建 / 更新时间等）。搜索框保持现网「不会真正过滤」，不要在原型里修好。

#### 拦截请求 `intercept-requests`

补列表总数、空态 / 加载失败可重试；详情中的错误类型、错误信息；白名单为「是」时展示匹配配置编号。

#### 拦截统计 `intercept-stats`

补各分布（域名 / 方法 / 状态码）的标题与空态「暂无 xx 数据」、加载中与失败可重试；每日请求空态「暂无每日记录」。汇总指标与现网一致。

#### 视频发布 `video-publish`

与现网差距大，按 `frontend/src/pages/video-publish` 复刻完整流程，而不是「简介 + 一个新建表单 + 一张任务表」。至少包括：选择并预览本地 MP4、设备与相册、创建任务与续传（须使用原文件名和原大小）、上传进度、二进制完成后须明确点击「确认上传并入队」（尚未发布）、队列确认对话框、任务详情中的发布内容 / 目标与进度 / 对象信息 / 人工确认审计 / 执行历史 / 资源清理 / 脱敏诊断、放弃草稿确认、发布配置与服务端能力、能力不足时的提示。用示例状态演示各阶段（上传中、待确认、已入队、失败、续传等）。

#### 素材 `media-assets`

补素材标签（已有 / 可选 / 新增）、上传各阶段（准备、传输进度、等待存储、核对入库）、预览与重新获取预览、编辑素材、素材包的新建 / 加入 / 添加视频、哪些数字人在用、所在素材包。不要只做简略的上传框和详情卡。

#### 数字人 `digital-humans`

补形象照片上传（格式与大小限制、预览、更换 / 选择照片）、为某人添加素材（搜索、勾选、隐藏已选、确认添加数量）、从本页上传新素材、关联素材管理与移除、档案详情结构。若现网仍保留「关联素材（较旧入口仍可用）」，原型一并保留。

#### 换装视频生成 `runninghub`

按现网补任务 / 批次状态（待启动、派发中、云端排队 / 生成、下载、成片处理、失败、待管理员核对、待续跑、已终止等）；单任务详情与成片预览；批次成片 ZIP；创建批次与生成计划（账户与运行配置、参考视频多选与生成顺序、更新工作流版本）；确认终止、继续生成剩余段、管理员核对（如「我已核实云端未创建任务」、校验成片）；批次记录。不要把页面收成「选图 + 选人 + 一张计划表」。

## 6. 验收标准

1. 逐页对照现网（或对应的 `frontend/src/pages/*`）：分区结构一致；现网可见的指标、字段、表格列、操作入口在原型中都能找到，并且位置关系正确（谁在哪张卡片/哪个对话框里）。
2. 不允许再用「中保真摘要」替代现网信息结构。例如不得把「销售 / 成本 / 利润」三栏经营概览压成一排指标卡，也不得把视频发布、素材、运行配置等页收成缺少关键步骤的简表。
3. 02 已通过且仍有效的项保持不变：三种预置角色与上限、tokens 与壳层、可离线打开、示例数据有标注、尚未拍板的取舍不进入原型。
4. 登录页此前作为「非阻塞」记下的三项（装饰图、eyebrow、密码可见切换）纳入本次，并补上不确定登录后的会话核对流程。
5. 完成后由产品按本文件逐页验收，不再沿用 `02` 第 9 节的通过结论。
