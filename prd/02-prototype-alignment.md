# 原型对齐现网（补需求）

> 状态：第 9 节原验收结论已被 `03-prototype-full-replica.md` 取代（2026-11-12）。tokens、壳层、三种预置角色与上限仍有效；各页正文按现网复刻未通过，改走 03。  
> 日期：2026-11-12  
> 提出人：chen  
> 范围：只改 `prd/prototypes/` 的可点击原型，不改线上业务代码，也不提前落地尚未拍板的产品取舍。

## 1. 背景

`prd/prototypes/` 已按现有功能反推出可点击原型，信息架构和页面范围已与架构师对齐。但原型视觉跟错了已归档的「暖纸编辑体」文档，和现网工作台的配色、控件、壳层不一致。chen 要求先把原型做成与线上一致，再处理其他产品取舍。

## 2. 目标

让 `prd/prototypes/` 在**交互逻辑**和**视觉语言**上，都与当前运营工作台（`/v2/pages/*` 的 React/HeroUI 实现）保持一致。评审时打开原型，应能对上现网在用的流程、权限、字段和界面气质，而不是另一套旧色板的示意图。

真相源依次为：

1. v2 源码（`tts_erp_v2/accounts/pages.py`、`frontend/src/`、`tts_erp_v2/static/css/tokens.css`）
2. 已校准的 `prd/00-prd.md`、`prd/01-information-architecture.md`、各页文档
3. 过时文档（含已归档的 `docs/archive/ui-style-system.md`）一律不作为依据

若文档与代码冲突，以代码为准。

## 3. 目标用户与使用场景

- 产品评审、需求对齐：对照原型看现有能力，而不是设想中的改版。
- 架构师后续写技术方案时，以这套对齐后的原型为界面与流程参考。

## 4. 用户故事

- 作为评审者，我在原型里走一遍登录、导航、各业务页和权限切换，看到的页面范围、可写/只读、字段、上限和关键流程应与现网一致，以免按错误逻辑做后续方案。
- 作为评审者，我打开原型时，配色、导航、内容面板和常用控件应跟现网是同一套视觉语言，以免把已废弃的暖纸/陶土橙色板当成现行设计。

## 5. 功能范围

### 5.1 要做

- **逻辑对齐**：逐页核对并修正原型，使其与现网一致，至少包括：
  - 只有一套 `/v2/pages/*` 工作台；不把订单、售后、结算画成独立工作台页面。
  - 登录为用户名 + 密码；工作台无改密入口、无 API key 签发/轮换/吊销页面。
  - 新店接入授权说明页（`oauth-onboard`）只是跳板，不是独立业务中心。
  - 预置角色与代码一致：系统管理员可进全部页面；运营可读写但排除「用户管理」和「视频发布」；只读分析仅可访问仪表盘、重点关注 SPU、SPU ROI、广告日明细、拦截统计，且全部只读禁写。
  - 重点关注页按现网：隐藏价格统计，明细表无「实际ROI」列；关注清单一次上限 500（100 是 ROI 页临时多选上限，不要写错）。
  - 拦截配置页的搜索框若现网无效，原型保持同样现状，不要在原型里“顺手修好”。
  - 五款 Chrome 插件不单独出插件界面原型；工作台已露出的部分（拦截三页、广告日明细、店铺插件发现、运行配置承载的监控策略等）仍按工作台页面表达。
- **视觉对齐**：原型改用现网 `tokens.css` 色板与壳层气质，不再使用已归档的暖纸编辑体（米色纸底、陶土橙、深棕导航）。现行要点：
  - 浅绿灰纸面（`--paper: #F5F5F0`）、白色内容面板（`--surface: #FFFFFF`）
  - 墨绿主色与导航（`--accent: #214F43`，`--navigation-background` 为 `#173F36`）
  - 导航激活色为浅青绿（`--navigation-active: #D8E6A2`）
  - 文字为墨绿灰层级，描边为浅灰绿
  - 圆角与现网一致（令牌 `--radius: 0.625rem`，面板/表格按工作台实际取值）
  - 侧栏为文字导航 + 当前页指示，不使用原型里自造的字母图标；桌面侧栏可折叠的行为与现网一致
  - 按钮、输入、表格、分页、对话框等控件样式贴近现网 HeroUI 工作台，而不是另一套自定义外观
- 原型仍可离线打开，仍使用示例数据、不连接后端。顶栏「原型角色」切换可保留，仅用于演示权限差异，但其权限结果必须与预置角色一致。

### 5.2 不做

- 不修改线上业务代码、不改现网样式实现。
- 不把 chen 尚未拍板的产品取舍做进原型或现网，包括：预置运营是否包含视频发布、只读是否进入利润劣化页、利润劣化页是否改名、是否补改密入口、拦截配置无效搜索框是补齐还是去掉。
- 不新做插件 Popup/扩展设置原型，不新做 API key 管理页面。
- 不把文档里的过时色板或已归档设计重新当成规范。

## 6. 验收标准

1. 用现网账号可见的页面、菜单分组、权限（含只读禁写）与原型在三种预置角色下一致。
2. 各页的关键字段、筛选项、按钮可用性、数量上限、空态/跳转（含授权跳板）与现网一致；不得出现现网没有的业务页或现网已拿掉的列。
3. 原型配色取自当前 `tts_erp_v2/static/css/tokens.css`，侧栏、内容区、控件外观与现网工作台明显同一套视觉语言，不再出现陶土橙主色或米色暖纸底。
4. 仍可离线打开 `prd/prototypes/index.html`（或同目录静态服务），示例数据有标注，不连接后端。
5. 若核对中发现文档与代码不符，以代码为准，并在对应页面文档或 `00-prd.md` 缺口中客观记录；不把发现写成改造承诺。

## 7. 优先级

P0。在 chen 拍板其他产品取舍、架构师出技术方案之前先完成。

## 8. 交付说明

- 改动目录：`prd/prototypes/`，必要时同步修订 `prd/00-prd.md`、`prd/README.md` 和相关页面文档中关于原型视觉或逻辑的过时描述。
- 由架构师给出必要的实现安排，再交给开发实施。产品不指定技术实现方式。
- 完成后由开发向架构师汇报改了哪些页、如何打开验收；产品按上述验收标准核对。
